# Futures MTF Lab — سناریوی معاملاتی چندتایم‌فریمی (PAPER)

نسخه: `2026-10-28.1` · **فقط کتابخانهٔ استاندارد پایتون** (بدون numpy / pandas /
requests / pyyaml / pytest) · اجرا روی هر PC، گوشی (Termux) و VPS بدون `pip install`.

> **این اپ مستقل از `apps/futures-scalp-lab` (سناریوی قدیم) است.** هیچ فایلی از آن
> تغییر نکرده؛ اتصال فقط از طریق `mtflab/compare.py` و به‌صورت فقط‌خواندنی است تا
> داشبورد مقایسه ساخته شود.

> **اصل طلایی:** هیچ عددی «سود واقعی» نیست مگر روی دادهٔ واقعی و out-of-sample،
> پس از کسر کامل هزینه، و با اختلاف معنادار از خط پایه. LIVE عمداً پیاده نشده است.

## ۱) این اپ چه می‌کند؟

| قابلیت | توضیح |
|---|---|
| **هم‌ترازی سه‌لایه** | بایاس (4h) + فیلتر رژیم (1h) + تریگر ورود (15m) — با هم‌ترازی تست‌شده و بدون lookahead |
| **سه نسخهٔ هم‌راستایی** | A (AND سخت‌گیرانه) · B (امتیاز وزنی) · C (فقط فیلتر رژیم) |
| **فیلتر اقتصادی هزینه** | سیگنالی که حرکت مورد انتظارش < ۱.۵× هزینهٔ رفت‌وبرگشت باشد رد می‌شود |
| **مدیریت ریسک** | ریسک ۱٪ موجودی، SL 1.5×ATR، TP 3×ATR، تریلینگ بعد از +1R، کول‌داون، مدار شکن، حد ضرر روزانه |
| **فورنزیک کامل** | هر سیگنال/وتو/معامله در JSONL با اسنپ‌شات همهٔ لایه‌ها، MFE/MAE و تشخیص دلیل سود/ضرر |
| **اعتبارسنجی** | split 60/20/20 · walk-forward ۶ پنجره با انتخاب مجدد آستانه · مونت‌کارلو ۱۰۰۰ · حساسیت · خط‌های پایه · چک‌لیست overfit |
| **داشبورد مقایسه** | HTML خودکفا با ۵ تب، مقایسهٔ سناریوی قدیم و جدید روی دادهٔ یکسان |
| **دانلودر Bybit** | دادهٔ عمومی بدون API key، با صفحه‌بندی، کش CSV و retry |

## ۲) نصب و اجرا (سه دستور)

```bash
cd apps/futures-mtf-lab

# ۱) خودآزمایی — قبل از هر کاری
python3 -m mtflab selftest

# ۲) مقایسهٔ سناریوی قدیم و جدید روی همان دادهٔ واقعی موجود + ساخت داشبورد
python3 -m mtflab compare \
  --csv ../futures-scalp-lab/data/btcusdt_1h_lastyear.csv \
  --out results/dash_scenarios.html

# ۳) گزارش تشخیصی: چرا سود کم برداشت می‌شود + آزمون سود شناور
python3 -m mtflab diagnose \
  --csv ../futures-scalp-lab/data/btcusdt_1h_lastyear.csv \
  --tf-trigger 1h --tf-filter 4h --tf-bias 1d --align A --bias-ema 50 \
  --out results/diagnosis_report.md

# ۴) دیدن داشبورد در مرورگر
python3 -m mtflab serve --dir results --port 8080
#   → http://localhost:8080/dash_scenarios.html
```

## ۳) دانلود دادهٔ 15m و اجرای طراحی اصلی سناریو

سناریو برای **15m / 1h / 4h** طراحی شده، ولی دادهٔ 15m در ریپو نیست
(و از 1h هم ساخته نمی‌شود — `resample_up` اجازه نمی‌دهد). روی PC خودت:

```bash
# حدود ۲ سال دادهٔ سه تایم‌فریم (بدون API key)
python3 -m mtflab download --symbol BTCUSDT --days 730

# بک‌تست + اعتبارسنجی کامل روی 15m
python3 -m mtflab validate --data bybit --symbol BTCUSDT \
  --tf-trigger 15m --tf-filter 1h --tf-bias 4h --align A

# مقایسهٔ نسخه‌های A/B/C (هر کدام یک اجرای مستقل)
python3 -m mtflab run --data bybit --symbol BTCUSDT --align B
python3 -m mtflab run --data bybit --symbol BTCUSDT --align C
```

## ۶.۱) تطبیق زنده (`mtflab evolve`) — آزمون نهایی روی ۵.۷ سال داده

ایده: بعد از هر معامله، تنظیمات بازنویسی شود. پیاده‌سازی محافظت‌شده:

- **τ (خون‌سردی)**: یک عدد پیوسته که همهٔ «فاصله‌ها» را با هم می‌کشد/جمع می‌کند
  (استاپ، TP، تریل، حداقل edge). `τ=۱` = دقیقاً فرمول فعلی.
  دامنهٔ آزمایش‌شده: `{0.75, 0.85, 1.0, 1.15, 1.3}`.
- **تغییر ساختاری سطحی**: حداکثر یکی از سه گزینه (`none`/`pullback`/`climax_1.0`)
  و آن هم با **میخ‌کشی** λ=۰.۵.
- **فیت روی گذشته، ارزیابی روی آیندهٔ دیده‌نشده** — هیچ نگاهی به جلو.
- **دو حالت**: `strict` (دروازهٔ آماری) و `rolling` (بهبود + بازگشت به ثابت).
- **توزیع پلاسیبو**: ۵ اجرای تصادفی روی همان ماشین (`--placebo-seeds 5`).

داده: **BTCUSDT ۵.۷ سال + ETHUSDT ۴.۷ سال = ۱٬۴۴۲ معامله** (۶ برابر آزمون قبلی).

| اجرا | ارتقا | expectancy تطبیقی | ثابت (همان پنجره‌ها) |
|---|---:|---:|---:|
| `strict` | ۰ | −۱.۱۹$ | −۱.۱۹$ |
| `rolling` | ۷ | **−۰.۷۱$** | −۱.۱۹$ |

در نگاه اول `rolling` بهتر به‌نظر می‌رسد (+۰.۴۸$). ولی **توزیع پلاسیبو** حکم را عوض می‌کند:

| اجرا | expectancy |
|---|---:|
| **واقعی** | **−۰.۷۱$** |
| پلاسیبو #1..#5 | −۱.۰۶ · −۰.۶۱ · −۱.۲۸ · −۰.۵۹ · −۰.۸۶ |

میانگین پلاسیبو −۰.۸۸$ ± ۰.۲۹ · نتیجهٔ واقعی در **صدک ۶۰** و **z=۰.۵۷**.
یعنی نتیجهٔ واقعی داخل تودهٔ تصادفی است؛ دو اجرای تصادفی از آن **بهتر** بودند.

**حکم: منبع بهبود، «مهارت انتخاب» نیست، فقط «ثابت نماندن» است.** با هیچ‌کدام از
این دو نتیجه نمی‌شود گفت موتور یادگیری چیزی کشف کرد.

## ۶.۱.۵) 🎯 یافتهٔ اصلی پروژه: `trend_4h` (روندکاوی کلاسیک روی تایم‌فریم بالا)

بعد از اینکه همهٔ راه‌های «تنظیم پارامتر» رد شدند، یک **تغییر ساختاری** امتحان شد و
تنها چیزی بود که زنده ماند:

| تغییر | چرا کار می‌کند |
|---|---|
| تریگر `1h → 4h` | تعداد معامله ۲.۵ برابر کم می‌شود ⇒ هزینهٔ ۰.۱۵٪ رفت‌وبرگشت به همان نسبت کم می‌شود |
| `TP 3×ATR → بدون TP` | در نسخهٔ قبلی هر برنده در ۲R قطع می‌شد ولی ضررها تا −۱R می‌رفتند. در بازار روندی این ساختار معکوس است |
| `تریل 2×ATR → 3×ATR` | فضای نفس برای روند |
| حذف بایاس ۱d | وتوی بایاس، معاملات خوب را می‌کشت |

**نتیجه روی BTCUSDT (۵.۷ سال، ۴۴۲ معامله):** PF **۱.۰۷۷** · expectancy **+۰.۷۶$** ·
بازده **+۳۳.۷٪** · MaxDD **−۲۷.۱٪** · نرخ برد ۲۷.۴٪ (کم‌برد، دنبالهٔ چاق — امضای روندکاوی)

**سال‌به‌سال BTC — هر شش سال مثبت:**
`2020 +153$ · 2021 +44$ · 2022 +50$ · 2023 +67$ · 2024 +179$ · 2025 +115$`

**فلات پارامتری (۳ سال اخیر، BTC):** TP از ۳×ATR تا بی‌نهایت و تریل ۲..۳ همه مثبت و
یکنوا — این «قله» نیست، «فلات» است:

| TP | تریل | PF | بازده |
|---|---|---|---|
| 3×ATR | 3.0×ATR | 1.24 | +۱۳.۹٪ |
| 6×ATR | 3.0×ATR | 1.54 | +۲۵.۱٪ |
| بدون TP | 3.0×ATR | **2.02** | **+۳۷.۹٪** |

**قیدهای صادقانه (همه با همان دروازهٔ سخت‌گیر سنجیده شد):**
- روی **ETH ضعیف** است: PF ۰.۹۰، −۲۶.۶٪ (پس این edge مخصوص BTC است، نه یک قانون بازار)
- آزمون بقا: ۵ از ۱۲ پنجره مثبت (۴۱.۷٪) — از ۱۶.۷٪ نسخهٔ پایه خیلی بهتر، ولی زیر شرط ۵۵٪
- آخرین پنجره (۲۰۲۵) منفی بود
- همچنان از **buy & hold** خیلی عقب‌تر است (+۳۳.۷٪ در برابر +۱۲۵۳٪)، ولی با MaxDD بسیار کمتر

⇒ این **یک سرنخ قوی و ساختاری** است، نه یک edge اثبات‌شده.

```bash
python3 -m mtflab run --data csv --csv ../futures-scalp-lab/data/btcusdt_1h_bybit.csv \
  --preset trend_4h --align A --fee-bps 5.5 --slippage-pct 0.02
```
