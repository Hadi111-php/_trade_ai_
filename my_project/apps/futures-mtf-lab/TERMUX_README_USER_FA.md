# 📱 اجرای اسکن خودکار روی گوشی (Termux)

این تنها کاری است که باید روی گوشی انجام دهید. کل فرایند خودکار است:
دانلود داده → ذخیره در JSON → تحلیل → گزارش.

## ۰) نصب یک‌باره (فقط بار اول)

Termux را از **F-Droid** نصب کنید (نسخهٔ Play Store قدیمی است و مشکل دارد).

```bash
pkg update -y && pkg install python git -y
```

بعد پروژه را بگیرید. ⚠️ **حتماً با نام برنچ** — کد روی شاخهٔ `main` نیست:

```bash
git clone -b arena/444f3300-trade-ai --single-branch --depth 1 \
  https://github.com/Hadi111-php/_trade_ai_.git lab
cd lab
```

> اگر `git clone` بدون `-b` بزنید، پوشهٔ `futures-mtf-lab` اصلاً وجود ندارد.
> مخزن عمومی است، پس نام کاربری/توکن لازم نیست.
> `--depth 1` حجم دانلود را کم می‌کند (مناسب گوشی).

> هیچ `pip install` لازم نیست. تمام کد با کتابخانهٔ استاندارد پایتون نوشته شده.

## ۱) اجرا (یک دستور — از ریشهٔ پروژه)

```bash
bash run-auto.sh
```

> ✅ لازم نیست وارد پوشهٔ اپ شوید. یک لانچر در ریشهٔ مخزن هست که خودش مسیر درست را
> انتخاب می‌کند. اگر از پوشهٔ اپ اجرا کنید هم کار می‌کند — هر دو مسیر پشتیبانی می‌شوند.

### 📖 زبان خروجی روی گوشی

ترمینال Termux خط فارسی را **برعکس و جدا** نشان می‌دهد (بدون پشتیبانی BIDI/شکل‌دهی).
برای همین، روی Termux خروجی **خودکار انگلیسی** می‌شود. اگر فارسی می‌خواهید:

```bash
bash run-auto.sh --lang fa
```

فایل گزارش (`.md`) هم با `--lang en` انگلیسی و با `--lang fa` فارسی نوشته می‌شود.
اگر فارسی خوانا نبود، فایل `.md` را با یک برنامهٔ دیگر (مثل Markdown viewer) باز کنید.

### اگر شک کردید کد به‌روز است یا نه

`bash run-auto.sh --status` را بزنید. سه چیز را نشان می‌دهد:

| خط | معنی |
|---|---|
| `🔖 کامیت` | نسخهٔ کدِ شما |
| `🔄 به‌روز؟ : بله ✅` | همان آخرین نسخه — ادامه بدهید |
| `🔄 به‌روز؟ : خیر ❌` + فهرست کامیت‌ها | کلون عقب است → همان دو دستور پایین را بزنید |

اگر جایی پیام `گزینه‌های ناشناخته` دیدید، **یعنی کلون عقب است**، نه این‌که
دستور غلط است. اول به‌روزرسانی، بعد دوباره همان دستور.

### نکات مهم در طول اجرا

- 📱 **گوشی را روشن نگه دارید.** اگر Termux را ببندید، دانلود قطع می‌شود.
  (اگر `termux-api` نصب باشد، اسکریپت خودش `wake-lock` می‌زند تا گوشی نخوابد:
  `pkg install termux-api -y`)
- 🔌 به شارژ وصل کنید.
- 📶 وای‌فای بهتر از دادهٔ همراه است.
- ⛔ **اگر وسط کار قطع شد، نگران نباشید.** دوباره `bash run-auto.sh` بزنید؛
  داده‌های دانلودشده ذخیره شده‌اند و از همان‌جا ادامه می‌دهد.

### اگر Bybit فیلتر بود

اسکریپت اول شبکه را چک می‌کند و اگر در دسترس نبود، صریح می‌گوید. در آن صورت:

0. 🚀 **فوری‌ترین راه — بدون اینترنت هم کار می‌کند:**
   ```bash
   bash run-auto.sh --offline
   ```
   دادهٔ ۵ سالهٔ BTC و ETH همراه خود پروژه هست؛ همین حالا تحلیل می‌شود
   (۲ نماد → دروازهٔ ۸ نمادی باز نمی‌شود، ولی کل مسیر و خروجی‌ها تست می‌شوند).

1. برای دیدن **علت دقیق** مسدود بودن:
   ```bash
   python3 -m mtflab autoscan --probe-only
   ```
   خروجی مشخص می‌کند «ساعت سرور» باز است یا «دادهٔ کندل» هم بسته شده.

2. VPN/پروکسی را روشن کنید و دوباره اجرا کنید
2. یا اگر آدرس آینه/پروکسی دارید، مستقیم بدهید:
   ```bash
   bash run-auto.sh --base-url https://your-proxy.example.com
   ```
3. یا اگر قبلاً داده گرفته‌اید، فقط تحلیل را دوباره اجرا کنید (آفلاین):
   ```bash
   bash run-auto.sh --source json
   ```

## ۳.۵) اجرای سناریوی اصلی اسپک (۱۵m / ۱h / ۴h)

تا امروز همهٔ اسکن‌های چندنمادی روی `4h` (فیلتر/بایاس `1d`) اجرا می‌شدند —
یعنی یک **جایگزین**. سناریوی اصلی طراحی (تریگر ۱۵ دقیقه) هرگز روی دادهٔ واقعی
آزموده نشده بود. حالا اجرا می‌شود:

```bash
bash run-auto.sh --tf 15m --tf-filter 1h --tf-bias 4h --days 730 --tag 15m
```

| نکته | توضیح |
|---|---|
| **زمان** | ۱۵m یک‌چهارمِ ۱h است ⇒ ~۷۰٬۰۰۰ کندل در نماد. با `--days 730` و ۲۰ نماد حدود **۴۵–۹۰ دقیقه** (دانلود ~۲۰ دقیقه + بک‌تست). اول با ۳ نماد زمان‌سنجی کنید (پایین) |
| **حجم** | هر نماد ~۷۰٬۰۰۰ کندل ⇒ پوشهٔ `data/json` چند صد مگابایت می‌شود. بعد از ارسال گزارش می‌توانید پاک کنید |
| **قطع شدن** | ایراد ندارد. دوباره همان دستور را بزنید؛ نمادهای تمام‌شده از کش خوانده می‌شوند |
| **زمان‌سنجی اول** | `bash run-auto.sh --tf 15m --tf-filter 1h --tf-bias 4h --days 730 --tag t3 --symbols BTCUSDT ETHUSDT SOLUSDT` — زمان هر نماد را نشان می‌دهد؛ اگر بیش از ۳ دقیقه بود، ۲۰ نماد را نصف کنید |
| **`--days 1460`** | چهار سال ۱۵m = ~۱۴۰٬۰۰۰ کندل در نماد. فقط اگر گوشی و اینترنت خوب است |
| **گرم نگه داشتن** | `termux-wake-lock` بزنید تا اندروید اسکریپت را نکشد |
| **سلامت داده** | هر نماد قبل از ورود به حکم بررسی می‌شود: آخرین کندل باید حداکثر ۲ روز عقب‌تر باشد و بیشتر از ۵٪ کندل‌های بازه غایب نباشد. وگرنه آن نماد **حذف** می‌شود و دلیلش در گزارش می‌آید — به‌جای این‌که بی‌صدا نتیجه را خراب کند |
| **هزینه** | در ۱۵m کارمزد سهم بزرگ‌تری از حرکت است؛ فیلتر هزینه (`min_edge_multiplier`) اینجا واقعاً فعال می‌شود — در ۱h عملاً بی‌اثر بود |

اگر ترکیب تایم‌فریم را اشتباه بدهید (مثلاً فیلتر ریزتر از تریگر)، **قبل از هر
دانلودی** با پیام روشن رد می‌شود:

```
❌ Invalid timeframe stack: `--tf-filter=1h` is finer than the trigger `4h`.
   Hint: --tf 15m --tf-filter 1h --tf-bias 4h
```

خروجی برای من: همان دو فایل `auto_scan_15m.md` و `auto_scan_15m.json` (بخش ۲).

## ۳.۶) انبار داده و زمان (UTC)

هر کندلی که یک‌بار دانلود شد، در `data/json/` می‌ماند و در یک فهرست ثبت می‌شود:

```bash
bash run-auto.sh --data-index          # چه داده‌ای داریم؟ (بدون شبکه)
bash run-auto.sh --data-index --deep   # صحت فایل‌ها را هم چک کن
```

| ستون | معنی |
|---|---|
| `از / تا (UTC)` | اولین و آخرین کندل، به وقت جهانی |
| `وضعیت` | `ok` = فایل سرجایش · `changed` = دست‌کاری/عوض شده · `missing` = پاک شده |

برای تست بعدی **هیچ دانلودی لازم نیست**:

```bash
bash run-auto.sh --source json --tag rerun
```

قواعدی که کد رعایت می‌کند:

- **همه‌چیز UTC است.** زمان کندل‌ها یونیکس میلی‌ثانیه‌اند؛ مرز کندل روزانه
  ۰۰:۰۰ UTC است، نه نیمه‌شب تهران. یک تست مخصوص همین وجود دارد که نتیجه را در
  چهار منطقهٔ زمانی مقایسه می‌کند و باید **دقیقاً یکی** باشد.
- **کش فقط اگر به‌اندازهٔ کافی بلند باشد پذیرفته می‌شود.** اگر یک‌بار ۷۳۰ روز
  گرفته باشید و بعد `--days 1460` بزنید، دوباره دانلود می‌کند — وگرنه گزارش
  «۴ سال» روی ۲ سال داده نوشته می‌شد.
- **دادهٔ ثانیه‌ای یا میکروثانیه‌ای** (CSVهای بیرونی) خودکار به میلی‌ثانیه
  تبدیل می‌شود؛ تاریخ متنی (مثل `2024-01-01`) با خطای روشن رد می‌شود چون
  منطقهٔ زمانی ندارد.

## ۳.۷) بایگانی داده (بعد از هر اجرا)

دادهٔ کامل روی گوشی می‌ماند؛ ۹۰ مگابایت را نمی‌شود در گیت گذاشت. اما
**شناسنامه**اش چند صد کیلوبایت است و همه‌چیز را ثابت می‌کند:

```bash
bash run-auto.sh --archive --tag 15m
```

خروجی: `data_archive/data_digest_15m.json` + `.md`

| داخلش چیست |
|---|
| `sha256` هر فایل (کشف تغییر یک بایت) |
| `content_sha256` روی هر شش ستون OHLCV |
| بازهٔ UTC، تعداد کندل، `days_requested` |
| کندل ماهانه (برای تحلیل خام) + بستهٔ روزانه |
| نمونهٔ ۳ کندل اول و ۳ کندل آخر (عیناً) |

**فقط فایل JSON را بفرستید** — همین برای بایگانی در گیت کافی است.

فایل خودکار به پوشهٔ **Download گوشی** هم کپی می‌شود (اگر `termux-setup-storage`
را یک‌بار زده باشید). اگر کپی نشد، مسیر کامل را خودش چاپ می‌کند.

### بعداً: آیا داده عوض شده؟

پس از هر دانلود دوباره:

```bash
bash run-auto.sh --verify-archive
```

| خروجی | معنی | کار |
|---|---|---|
| `identical` | داده دست‌نخورده | هیچ |
| **`changed`** | صرافی تاریخ را بازنویسی کرده | نتایج قبلی باید دوباره اجرا شوند |
| `moved` | پنجره جابه‌جا شده (پنجرهٔ غلتان) | طبیعی است، هش قابل مقایسه نیست |
| `missing` | آن نماد در یک طرف نیست | اگر عمدی نبوده، نگاه کن |

## ۳.۸) تحلیل هزینه — «آیا هزینه کشنده است یا سیگنال؟»

**چرا این مهم است:** هر بهبود اجرا (سفارش محدود، کارمزد میکر، اسلیپیج صفر) فقط
یک کار می‌کند: هزینه را کم می‌کند. پس بهترین چیزی که می‌تواند بدهد، همان حالت
«هزینهٔ صفر» است. اگر با هزینهٔ صفر هم سودده نبود، هیچ اجراگذاری نجاتش نمی‌دهد.

```bash
bash run-auto.sh --sweep --tf 4h
```

بدون دانلود، روی دادهٔ ذخیره‌شده. حدود ۲ دقیقه برای ۲۰ نماد و دو نسخه (`trend` و `base`).

> **اگر فایل را پیدا نکردید:** گزارش، مسیر **مطلق** فایل را چاپ می‌کند و خودش آن را
> در پوشهٔ Download گوشی کپی می‌کند. اگر Download در دسترس نبود، همان‌جا می‌نویسد
> فایل‌ها کجا هستند و دستور کپی را هم چاپ می‌کند. فایل‌ها همیشه اینجا هم هستند:
> `my_project/apps/futures-mtf-lab/results/cost_sweep.*`

### چه چیزی اندازه می‌گیرد

| سیاست | ورود | خروج | هزینهٔ رفت‌وبرگشت |
|---|---|---|---:|
| `taker` | بازار ۵.۵bps + ۰.۰۲٪ | بازار | ۱۵ bps |
| `taker_noslip` | بازار بدون اسلیپیج | بازار | ۱۱ bps |
| **`maker_tp`** ★ | بازار | **حد سود = سفارش محدود** | **۹.۵ bps** |
| `all_maker` | همه میکر (غیرواقعی) | همه میکر | ۴ bps |
| `zero` | صفر | صفر | ۰ bps |

`maker_tp` واقع‌بینانه‌ترین است: در معاملهٔ الگوریتمی ورود و حد ضرر بازارند، ولی
حد سود یک سفارش محدودِ نشسته است. مدل قبلی هر دو پا را تیکر می‌گرفت — یعنی
**بدبینانه‌تر از واقعیت** بود.

### چطور بخوانید — حکم خودکار

گزارش در خط اول یک «حکم» می‌دهد. سه حالت ممکن است:

| حکم | معنی | کار بعدی |
|---|---|---|
| ❌ **رها کنید** | با هزینهٔ صفر هم PF ≤ ۱ | مسئله سیگنال است، نه اجرا |
| ✅ **طرح میکر ارزش ساخت دارد** | با `maker_tp` هم PF > ۱ | اجراگذاری محدود را بسازید |
| ⚠️ **مرزی** | فقط با `all_maker` بالای ۱ می‌رود | نسازید؛ حد ضرر را نمی‌توان محدود گذاشت |

**نکتهٔ کلیدی که گزارش نشان می‌دهد:** بخش «معامله‌ها چطور بسته می‌شوند» سهم
خروج‌هایی را می‌دهد که اصلاً می‌توانند محدود باشند. حدود دوسومِ خروج‌ها حد ضرر و
تریلینگ‌اند و **ماهیتاً سفارش بازارند**. پس اگر آن سهم کوچک باشد، ستون `maker_tp`
عملاً همان `taker` است و سودِ `all_maker` یک سراب است.

## ۳.۹) مدیریت خروج هر ۱۵ دقیقه — «کندل ۴ ساعته باز، ولی دقیقه‌به‌دقیقه دیده شود»

```bash
bash run-auto.sh --exec-scan
```

بدون دانلود. تصمیم **ورود** روی ۴ ساعته گرفته می‌شود، ولی پوزیشن باز با کندل
های **۱۵ دقیقه** مدیریت می‌شود: ۱۶ بررسی در هر کندل ۴ ساعته، نه یکی. حدود
۵ دقیقه برای ۱۶ نماد. دو فایل می‌سازد و به Download می‌گذارد: `exec_tf.md` و
`exec_tf.json`.

**به داشتن داده نیاز دارد:** هم `*_4h.json` و هم `*_15m.json` در `data/json/`.
از اجرای قبلی هر دو را داری. نمادهایی که فقط یک تایم‌فریم دارند، در گزارش
جدا فهرست می‌شوند و حذف می‌شوند (بی‌صدا نادیده گرفته نمی‌شوند).

### سه تنظیم — بدون جست‌وجو، از قبل قفل‌شده

| کد | چیست |
|---|---|
| `A_base` | پایه: همه چیز مثل امروز (۴ ساعته، بدون قاعدهٔ افت سود) |
| `B_fine` | خروج روی ۱۵ دقیقه: ترتیب واقعی لمس حد ضرر/حد سود + تریلینگ ۱۶ برابر سریع‌تر |
| `C_fine_gb` | همان `B` + **قاعدهٔ افت سود**: اگر سود شناور به +۱R رسید و بعد به ۵۰٪ اوجش برگشت، ببند |

### چرا «دقت مسیر» واقعاً مهم است

یک کندل ۴ ساعته می‌تواند هم سقف را لمس کند هم کف. مدل ۴ ساعته **نمی‌داند**
کدام اول بود، پس محافظه‌کارانه حد ضرر را فرض می‌کند. مدل ۱۵ دقیقه‌ای می‌داند.
این تنها جایی است که این ایده می‌تواند نتیجه را عوض کند — و تست
`test_fifteen_minute_detail_knows_the_take_came_first` همین را قفل کرده است.

### معیار قبولی — از قبل نوشته شده

| شرط | حد |
|---|---|
| میانهٔ PF | ≥ **۱.۱۲۰۱** (پایهٔ امروز) |
| نمادهای PF>1 | ≥ **۱۵** از ۲۰ |
| سهم ۵ سکهٔ اول از سود | **< ۷۰٪** |

هر سه باید **هم‌زمان** پاس شوند. PF بهتر با تمرکز بیشتر روی چند سکه، قبولی
نیست — همان دام overfitting است. حکم در ستون «قبولی» گزارش می‌آید.

## ۳.۱۰) آزمون قله/دره و «استراحت بعد از سود»

```bash
bash run-auto.sh --trade-lab
```

بدون دانلود، روی دادهٔ ۴ ساعتهٔ ذخیره‌شده. سه فایل می‌سازد و در Download
می‌گذارد: `trade_lab.md`، `trade_lab.json` و `trades_export.json`.

این یک اجرا، **دو سؤال** را جواب می‌دهد — و `trades_export.json` را نگه دارید،
چون هر آزمون آیندهٔ دیگری هم می‌شود روی همان اجرا کرد، بدون اجرای دوباره.

### آزمون ۱ — جایگاه قیمت میان قله و دره

۰ = روی دره · ۱ = روی قله · بالای ۱ = محدوده شکسته.

قله و دره **تأییدشده** حساب می‌شوند: یک قله فقط وقتی قله است که ۳ کندل بعدش هم
پایین‌تر باشد. یعنی قله در همان کندل معلوم نمی‌شود — همان نکته‌ای که جلوی نگاه
به آینده را می‌گیرد.

خرگوش این آزمون **پنجک‌بندی** است، نه جست‌وجوی آستانه: همهٔ معاملات به ۵ گروه
بر اساس نسبت تقسیم می‌شوند و میانگین هر گروه مقایسه می‌شود. اگر ویژگی اطلاعات
داشته باشد، این پنج عدد یکنوا بالا یا پایین می‌روند.

| دروازه (از قبل) | حد |
|---|---|
| اختلاف پنجک ۱ و ۵ | ≥ **۰.۳۱R** |
| معناداری | \|t\| ≥ ۲ |
| حداقل معامله در هر پنجک | ۶۰ |

### آزمون ۲ — «بعد از سود، سود را پس می‌گیرند؟»

پنج قاعده، همه از پیش تعیین‌شده (ترکیب زمان **و** ساختار، همان چیزی که
خواسته شد):

| قاعده | چیست |
|---|---|
| ۴ کندل صبر | بعد از هر برد، ۴ کندل (۱۶ ساعت روی ۴ ساعته) معامله نکن |
| ۴ کندل + تغییر ساختار | همان، ولی اگر ساختار بازار عوض شد، زودتر آزاد شو |
| ۲۰ کندل + تغییر ساختار | ≈۳ روز صبر |
| معاملهٔ بعدی | فقط معاملهٔ بعدیِ همان نماد را رد کن |
| معاملهٔ بعدی + تغییر ساختار | همان + آزادشدن با تغییر ساختار |

**دروازه:** بهبود expectancy باید ≥ **۰.۰۶R** باشد **و** از باند نویز بیرون بزند.
باند نویز با جابه‌جایی تصادفی برچسب برد/باخت درون هر نماد ساخته می‌شود — یعنی
همان قاعده روی داده‌ای که در آن اثر وجود ندارد اجرا می‌شود.

> اگر خروجی «⚪ بی‌اثر (هیچ معامله‌ای حذف نشد)» دیدید، یعنی معاملات آن‌قدر از هم
> دورند که ۴ کندل صبر هیچ اثری ندارد. این خودش یک یافته است، نه خطا.

## ۳.۱۱) اتوترید مجازی — رصد اعتبار سیگنال‌ها

```bash
bash run-auto.sh --live            # یک گام: دادهٔ تازه، سیگنال تازه، گزارش
bash run-auto.sh --live --status   # فقط گزارش وضعیت (بدون گرفتن داده)
```

این «ربات معامله» نیست — **دفترچهٔ رصد** است. هیچ سفارشی به صرافی نمی‌رود،
هیچ کلید API نمی‌خواهد، و همه‌چیز روی حسابِ خیالی (شروع: **۱۰۰۰$**) جلو می‌رود.
هدفش این است که ببینیم سیگنال‌های همین الگوریتم که الان نهایی است، در آینده
چه اعتباری دارند — بدون این‌که دوباره پارامتر عوض کنیم.

### هر اجرا چه می‌کند

۱. کندل‌های بستهٔ تازه را می‌گیرد (کندل نیمه‌کاره هیچ‌وقت استفاده نمی‌شود).
۲. فقط روی کندل‌هایی که **قبلاً ندیده** جلو می‌رود (شمارندهٔ `last_bar_ms` در
   `results/live/state.json`) — اجرای دوباره سیگنال تکراری نمی‌سازد.
۳. سیگنال را با **انتساب کامل** در `results/live/journal.jsonl` ثبت می‌کند.
۴. خروج‌ها را با قاعده‌ای که بست ثبت می‌کند و به همان سیگنال پیوند می‌دهد.
۵. گزارش فارسی `results/live_report.md` را می‌نویسد و در Download می‌گذارد.

### دو سؤالی که هر رکورد جواب می‌دهد

- **این سیگنال مالِ کدام الگوریتم بود؟** `algorithm.id` (مثل `trend`)،
  `algorithm.label`، `cfg_digest` (انگشت‌نگاری پارامترها) و `tf`.
- **چه الگویی سیگنالش کرد؟** `entry_pattern.mode` (breakout / pullback)،
   رژیم فیلتر و بایاس، دلیل تریگر و دلیل تصمیم، confidence و score.
- **چه چیزی بستش؟** `closed_by.rule` + یعنی‌فارسی‌اش + پرچم
  `is_risk_control` — یعنی **صریحاً معلوم است که آیا یک قاعدهٔ ضدضرر بستش یا نه**.

نمونهٔ یک رکورد بستن:

```json
{"type":"close","id":"BTCUSDT:trend:1704787200000:closed",
 "open_id":"BTCUSDT:trend:1704787200000",
 "closed_by":{"rule":"stop_trail","fa":"تریلینگ استاپ (ATR×ضریب)",
              "is_risk_control":true},
 "result":{"pnl":6.55,"r_multiple":0.65,"mfe_pct":1.93,"bars_held":18}}
```

`open_id` همان شناسهٔ سیگنال است. با یک `grep` می‌شود کل پروندهٔ یک معامله را دید:

```bash
grep "BTCUSDT:trend:1704787200000" results/live/journal.jsonl
```

### گزارش

| بخش | چه می‌گوید |
|---|---|
| سرمایه / اوج / افت | حساب مجازی چقدر جلو رفته |
| کدام الگوریتم، چند سیگنال | نرخ برد و expectancy هر الگوریتم (به R) |
| کدام قاعده بست | سهم هر قاعده + ✅ اگر ضدضرر بود |
| آخرین سیگنال‌های بسته‌شده | هر سیگنال: ورود، خروج، R، سود، قاعدهٔ بست |
| سیگنال‌های باز | با الگو و الگوریتم، برای این‌که بدانی الان چه چیزی در جریان است |
| سیگنال‌هایی که رد شدند | چرا وارد نشد: جایگاه پر بود، فیوز ضرر پیاپی، استراحت بعد از ضرر، سقف ضرر روزانه |

### حلقهٔ تکرار (روی گوشی)

هر ۴ ساعت یک کندل ۴ ساعته بسته می‌شود؛ پس روزی ۶ بار کافی است. این را در
Termux بزن و بگذار باز بماند:

```bash
while true; do
  bash run-auto.sh --live
  echo "--- خواب ۱ ساعت ---"
  sleep 3600
done
```

چرا ۱ ساعت و نه ۱۵ دقیقه؟ کندل ۴ ساعته است؛ داده تا سرِ کندل بعدی عوض نمی‌شود
و کشِ CSV همان را می‌خواند. پس اجرای ساعتی هم `bars=0` می‌دهد و هم درخواست
بی‌مورد به Bybit نمی‌فرستد.

اگر می‌خواهی فقط نگاه کنی و چیزی نخوابانی:

```bash
bash run-auto.sh --live --status
```

### نکته‌های مهم

- **دادهٔ کم = تاریخچهٔ کم.** اولین اجرا با `--backfill` (پیش‌فرض ۱۲۰ کندل)
  تاریخچه را از نو می‌سازد تا گزارش از روز اول خالی نباشد. این معاملات در
  ژورنال `"backfilled": true` دارند و با معاملات واقعیِ آینده قاطی نمی‌شوند.
- **پنجرهٔ داده کوچک نشود.** اگر بعداً با `--days` کمتر اجرا کنی و پوزیشنی
  قدیمی‌تر از پنجره باز باشد، پوزیشن دور ریخته **نمی‌شود**؛ با علامت
  `restore_gap` در حالت می‌ماند و از آخرین کندل مدیریت می‌شود.
- **دست نزن به پارامترها.** هر تغییری در پارامترها `cfg_digest` را عوض می‌کند؛
  یعنی سیگنال‌های قبل و بعد از تغییر دیگر یک خانواده نیستند. رصد فقط وقتی معنا
  دارد که الگوریتم ثابت بماند.
- **پاک کردن از صفر:** `rm -rf results/live results/live_report.*`

## ۳.۱۲) داشبورد کارگاه — «اتوترید» + «آزمایشگاه تنظیمات»

```bash
bash run-auto.sh --dash                 # داشبورد + یک قدم زنده
bash run-auto.sh --dash --no-step       # فقط داشبورد، بدون گرفتن داده
bash run-auto.sh --dash --every 3600    # داشبورد + حلقهٔ خودکار هر ۱ ساعت
```

بعد در مرورگر گوشی این را باز کن:

```
http://127.0.0.1:8770
```

هیچ چیز از اینترنت بارگذاری نمی‌شود (نه فونت، نه کتابخانه) — پس روی گوشیِ
بی‌اینترنت هم باز می‌شود. فقط PAPER است؛ نه کلید API، نه سفارش واقعی.

### چهار تب

| تب | چه می‌دهد |
|---|---|
| **زنده** | سرمایهٔ مجازی، افت، سیگنال‌های باز، آخرین بسته‌شده‌ها، و «چرا وارد نشد». دکمهٔ «قدم بعدی» یک قدم تازه می‌زند. |
| **سیگنال‌ها** | فهرست همهٔ سیگنال‌ها با فیلتر (نماد، قاعده، ضدضرر، باز/بسته). روی هر ردیف بزن تا **پروندهٔ کامل** همان سیگنال باز شود. |
| **آزمایشگاه** | ۲۷ تنظیم (ریسک، خروج، ورود، ساختار) + انتخاب نماد + **دروازه‌ای که قبل از اجرا می‌نویسی** → نتیجهٔ همان لحظه، با Δ، بازهٔ اطمینان و بخش بیرون‌نمونه. |
| **آزمایش‌ها** | همهٔ آزمایش‌ها با شمارهٔ ترتیب، هش تنظیمات و حکم دروازه. هیچ آزمایشی پاک نمی‌شود. |

### سه چیزی که عمداً سخت‌گیرانه گذاشته شده

۱. **شمارهٔ آزمایش**: هر اجرا می‌گوید «این چندمین آزمایش روی همین داده است» و
   احتمال این‌که دست‌کم یکی شانسی خوب به نظر برسد را می‌نویسد.
۲. **بازهٔ اطمینان Δ**: بهبود نسبت به خط پایه با بوت‌استرپ ۹۰٪ سنجیده می‌شود؛
   اگر بازه صفر را دربر بگیرد، یعنی «قابل اثبات نیست».
۳. **بخش بیرون‌نمونه**: ۳۰٪ آخرِ بازهٔ زمانی جدا سنجیده می‌شود. تغییری که فقط در
   گذشتهٔ دور خوب بوده، این‌جا لو می‌رود.

### نکتهٔ مهم دربارهٔ داده

آزمایشگاه روی **همان دادهٔ کش‌شده** اجرا می‌شود (بدون شبکه) و کش‌ها را در
`data/json` نگه می‌دارد. آزمایش‌ها در `results/live_lab/` ذخیره می‌شوند (در گیت
نمی‌روند). اگر داده تازه خواستی، در تب زنده «قدم بعدی» را بزن یا در Termux
`bash run-auto.sh --live` را اجرا کن.

## ۳.۱۳) مغز دوم — یک مشاور کوچک کنار اتوترید

```bash
bash run-auto.sh --brain                    # روی همهٔ نمادهای کش‌شده
bash run-auto.sh --brain --symbols BTCUSDT ETHUSDT SOLUSDT
```

بدون شبکه. خروجی: `results/brain_report.md` و `.json` (و کپی در Download).

### چه چیزی می‌سازد

از **همان معاملاتی که موتور می‌گیرد** یک مجموعه داده می‌سازد: ۱۲ ویژگی در
**لحظهٔ ورود** (ATR٪، ADX، RSI، جایگاه دانچیان، باند بولینگر، حجم z، ساختار،
شیب EMA، اطمینان تصمیم، الگو) و برچسب «برد/باخت». بعد یک **رگرسیون لجستیک
کوچک** روی آن می‌نشیند.

چرا مدل کوچک و خطی؟ با ~۴۰۰ معامله، هر پارامتر اضافه یک درِ تازه برای نویز است.
مزیت دومش این است که می‌شود پرسید «چرا این سیگنال را رد کردی؟» و جواب عددی
گرفت (ضریب هر ویژگی).

### آزمونش چطور است

**walk-forward**: داده به ۴ بلوک زمانی تقسیم می‌شود؛ مدل روی گذشته آموزش
می‌بیند و فقط روی بلوکِ بعدی پیش‌بینی می‌کند. هیچ نمونه‌ای از آینده در آموزش
نیست (تست جداگانه همین را قفل کرده).

### دروازه — قبل از دیدن نتیجه نوشته شده

| شرط | حد |
|---|---|
| پیش‌بینی بیرون‌نمونه | ≥ ۱۵۰ |
| اختلاف expectancy چهارک بالا و پایین | ≥ ۰.۳۰R |
| خودِ چهارکِ بالا | ≥ ۰R |
| Δ فیلتر (رد ۳۰٪ کم‌اعتماد) | بازهٔ ۹۰٪ کاملاً مثبت |
| نگه‌داشتن داده پس از فیلتر | ≥ ۵۰٪ |
| پایداری علامت سه ضریب اصلی در فولدها | ≥ ۶۶٪ |

اگر همه پاس نشد، مدل **وارد سیستم نمی‌شود** — حتی اگر AUC خوب باشد. این خط
قرمز است، چون تجربهٔ این پروژه نشان داد «بهبودِ خوب‌به‌نظررسیدن» ارزان است.

### اگر پاس شد، قدم بعد چیست

آن‌وقت (و فقط آن‌وقت) مدل به‌عنوان **رتبه‌دهنده** وارد اتوترید می‌شود: وقتی یک
جایگاه آزاد است و دو سیگنال هم‌زمان می‌آیند، آن را انتخاب می‌کند که مدل
می‌پسندد — و در ژورنال، `model_score` و `model_version` هم کنار بقیهٔ انتساب
ثبت می‌شود. مدل هرگز سیگنال تازه نمی‌سازد.

## ۳.۱۴) چشم مغز — مشاوری که فقط نگاه می‌کند

```bash
bash run-auto.sh --brain-view --train          # ساخت مدل + دیدگاه همهٔ نمادها
bash run-auto.sh --brain-view                  # فقط دیدن دیدگاه (بدون آموزش)
bash run-auto.sh --live                        # اتوترید؛ اگر مدل باشد، خودش نگاه مغز را ثبت می‌کند
bash run-auto.sh --live --no-brain             # اتوترید بدون نظاره‌گر
```

### معماری — سه لایهٔ جدا

| لایه | فایل | چه می‌داند | چه اجازه‌ای دارد |
|---|---|---|---|
| **چشم** | `mtflab/brainview.py` | اندیکاتورها و داده | فقط احتمال صعود یک روز آینده را بگوید |
| **نظاره‌گر** | `mtflab/observer.py` | همان مدل + کش | فقط **خواندن** دیدگاه؛ هیچ تصمیمی نمی‌گیرد |
| **الگوریتم‌یاب** | `mtflab/engine.py` + `live.py` | قواعد، فیلتر، ریسک | **حاکم** — تصمیم ورود و خروج فقط این‌جاست |

`brainview.py` هیچ‌جا `engine`/`live`/`signals` را ایمپورت نمی‌کند (تست
`test_view_module_knows_nothing_about_trading` این را قفل می‌کند). یعنی برای
این‌که مغز روی تصمیم اثر بگذارد، باید کد تازه نوشته شود — نه فقط یک پارامتر.

### در ژورنال چه ثبت می‌شود

هر رکورد `open` حالا یک فیلد `brain` دارد:

```json
"brain": {"available": true, "p_up": 0.435, "lean": "short",
          "confidence": 0.565, "horizon_bars": 6,
          "model": "brainview/1.0", "model_digest": "51dfa22791",
          "ts": 1721851200000,
          "drivers": [{"name":"bb_pos","fa":"جایگاه در باند","contrib":-0.05}]}
```

اگر مدل نباشد: `{"available": false, "reason": "no-model"}` — و اتوترید دقیقاً
مثل قبل کار می‌کند.

### گزارش «مغز چه می‌گفت»

گزارش روزانه یک جدول تازه دارد: سیگنال‌ها به سه گروه تقسیم می‌شوند —
**هم‌جهت** (مغز هم صعودی/نزولی می‌دید)، **مخالف**، و **بی‌طرف/بدون مغز** — و
expectancy هر گروه نشان داده می‌شود. این تنها راه صادقانه برای فهمیدن این است
که آیا مشاورهٔ مغز ارزشی دارد یا نه. اگر «هم‌جهت» بهتر نبود، مغز فقط تزئین است.

### آنچه عمداً نیست

- مغز **سیگنال نمی‌سازد** و **فیلتر نمی‌کند**.
- مغز حد ضرر/سود یا حجم را عوض نمی‌کند.
- مغز هیچ‌جا در مسیر تصمیم صدا زده نمی‌شود؛ فقط هنگام نوشتن رکورد.

## ۳.۱۵) «داشبورد بالا نیامد» — عیب‌یابی در سه گام

```bash
# گام ۱: معاینه (هیچ شبکه‌ای لازم نیست، ۱ ثانیه)
bash run-auto.sh --doctor

# گام ۲: بدون گرفتن داده بالا بیاور
bash run-auto.sh --dash --no-step

# گام ۳: اگر پورت شلوغ است، صریح پورت دیگر بده
bash run-auto.sh --dash --port 8790
```

### اول از همه: `--live` داشبورد نیست

| دستور | چه می‌کند | تمام می‌شود؟ |
|---|---|---|
| `bash run-auto.sh --live` | **یک قدم** اتوترید: کندل تازه → سیگنال → گزارش | ✅ بله، برمی‌گردد به خط فرمان |
| `bash run-auto.sh --dash` | **داشبورد وب** را باز می‌کند و منتظر می‌ماند | ❌ نه، تا `Ctrl+C` |

اگر `--live` زده باشی و جدول دیدی، داشبورد بالا نیامده — چون اصلاً صدایش نزده‌ای.
آخر گزارش `--live` حالا خودش این خط را چاپ می‌کند:
`💡 this was one step, not the dashboard → bash run-auto.sh --dash`

`--doctor` یک جدول می‌دهد و دقیقاً می‌گوید کدام چیز مانع است. سه علتِ واقعی که
تا حالا دیده شده:

| نشانه | علت | درمان |
|---|---|---|
| `OSError: Address already in use` | یک `--dash` قدیمی پورت ۸۷۷۰ را گرفته | `pkill -f 'mtflab live --serve'` — یا همان `--port 8790` |
| چند دقیقه سکوت، هیچ نشانی چاپ نمی‌شود | نسخهٔ قدیمی: اول کندل ۲۰ نماد را می‌گرفت، بعد سرور | نسخهٔ جدید اول سرور را بالا می‌آورد؛ `--no-step` هم هست |
| صفحه باز می‌شود ولی جدول‌ها خالی‌اند | کش داده خالی است (داشبورد سالم است) | `bash run-auto.sh --live` تا داده بیاید |

### چه چیزی عوض شد (نسخهٔ جدید)

1. **اول سرور، بعد شبکه.** سرور در کمتر از یک ثانیه بالا می‌آید و نشانی چاپ
   می‌شود؛ گرفتن کندل تازه در پس‌زمینه اجرا می‌شود و نتیجه‌اش چاپ می‌شود.
2. **پورت اشغال، مرگ نیست.** اگر ۸۷۷۰ گرفته باشد، خودش ۸۷۷۱، ۸۷۷۲ … را
   امتحان می‌کند و می‌گوید کدام را برداشته.
3. **مرورگر خودکار.** اگر `termux-api` نصب باشد، خودش مرورگر را باز می‌کند
   (`--no-open` برای خاموش‌کردنش).
4. **خروجی بی‌درنگ (flush).** قبلاً اگر خروجی به فایل می‌رفت، تا پایان کار هیچ
   چیزی دیده نمی‌شد؛ حالا هر خط همان لحظه چاپ می‌شود.

### اگر هنوز نیامد

این دو خروجی را برایم بفرست (کوتاه‌اند):

```bash
bash run-auto.sh --doctor
bash run-auto.sh --dash --no-step
```

نکتهٔ اندروید: Termux وقتی در پس‌زمینه است ممکن است توسط سیستم خوابانده شود.
برای اجرای طولانی، از `termux-wake-lock` استفاده کن و صفحه را روشن نگه دار.

## ۳.۱۶) تیم‌ها و تنظیمات در داشبورد — آزمایش بدون گول‌خوردن

```bash
bash run-auto.sh --dash            # داشبورد را باز کن
# تب «آزمایشگاه» → انتخاب الگو → تغییر تنظیمات → اجرای آزمایش
```

### «تیم» یعنی چه

تیم = **الگوی پایه + یک دسته تنظیماتِ نام‌دار**. هیچ منطق تازه‌ای اضافه نمی‌شود؛
همان موتور، همان داده، فقط با اعداد دیگر. پنج الگوی پایه از قبل هست
(`base`, `trend`, `trend_tp`, `pullback`, `climax`) و تو می‌توانی تنظیمات فعلی
را با یک اسم ذخیره کنی تا بعداً با یک کلیک برگردی.

> تیم **اعتبار آماری نمی‌دهد**. هر اجرا باز هم شمارهٔ آزمایش روی آن داده،
> Δ با بازهٔ اطمینان ۹۰٪، و بخش بیرون‌نمونه را کنار نتیجه می‌نویسد.

### چرا این با «پارامتر را دست نزن» تناقض ندارد

| کجا | هدف | پارامتر |
|---|---|---|
| داشبورد (این‌جا) | **کاوش**: ببینم چه چیزی به چه چیزی حساس است | آزاد، ولی هر اجرا ثبت و شماره‌گذاری می‌شود |
| آزمون‌های سالانه/عمده | **حکم**: آیا این لبه واقعی است؟ | قفل؛ دروازه **قبل** از دیدن نتیجه نوشته می‌شود |

خطر واقعی این است که نتیجهٔ کاوش را با حکم اشتباه بگیریم. برای همین شمارندهٔ
آزمایش و Δ با خط پایه اجباری است — نه برای بستن دست تو، برای این‌که بعداً بدانیم
چند بار نگاه کردیم.

### تنظیمات مغز در داشبورد

در تب «مغز دوم» دو آستانه هست: «صعودی اگر احتمال ≥» و «نزولی اگر احتمال ≤».
این‌ها **فقط برچسب** را عوض می‌کنند (🟢/🔴/⚪). هیچ معامله‌ای از آن‌ها خوانده
نمی‌شود و قرارداد نظاره‌گر دست‌نخورده است. آموزش مدل جداگانه است:

```bash
bash run-auto.sh --brain-view --train
```

### خط پایه برای هر تیم جداست

اگر تیم `pullback` را با تنظیمات تازه اجرا کنی، مقایسه با خط پایهٔ **همان تیم**
انجام می‌شود، نه با `trend`. قبلاً یک خط پایه برای همه بود و Δ بی‌معنا می‌شد.

## ۳.۱۷) راهنما، نقشهٔ کد، و بستهٔ مستقل

### راهنما داخل داشبورد

تب تازهٔ **«راهنما»** در همان صفحه: پنج تب در یک خط، سه عددی که تصمیم می‌سازند،
پنج قانون طلایی، و این‌که «ضررِ سالم» با «خطا» چه فرقی دارد. نسخهٔ کامل و
قابل‌چاپ: `docs/GUIDE_DASHBOARD_FA.md`.

### نقشهٔ کد — کدام فایل چه کاری می‌کند

`docs/ENGINE_MAP_FA.md` — دقیقاً همان چیزی که برای وصل‌کردن به یک داشبورد دیگر
لازم است:

| بخش | فایل |
|---|---|
| الگوها/تیم‌ها | `mtflab/patterns.py` |

### بستهٔ مستقل (برای دادن به داشبورد دیگر)

### چرا جدا از اتوترید است

| | اتوترید | پامپ و دامپ |
|---|---|---|
| تایم‌فریم | ۴ ساعت | ۱۵ دقیقه |
| محرک | ساختار روند + هم‌راستایی | انفجار حجم و دامنه |
| ریسک اصلی | نویز، هزینه | **اسپرد و لغزش**، دیر رسیدن |
| تعداد رویداد | هزاران معامله | ده‌ها تا صدها در سال |

پس موتور ۴ساعته را برای این کار «نیم‌فهم» به کار نمی‌بریم. `pumpdump.py` هیچ
`engine`/`signals` را ایمپورت نمی‌کند (تست AST دارد).

### تعریف یخ‌زدهٔ رویداد (تغییرش = آزمون تازه)

- دامنهٔ کندل ≥ **۲.۵×** میانگین ۵۰ کندل قبل
- حجم ≥ **۳×** میانگین همان بازه
- بسته‌شدن در **۲۵٪ بالای** دامنه (پامپ) یا پایین (دامپ)
- ورود: سیگنال روی بستهٔ کندل، پر شدن روی **بازِ کندل بعد**

### دروازهٔ شش‌شرطی (قبل از دیدن نتیجه)

۱. رویداد مستقل ≥ ۱۰۰ ۲. میانهٔ خالص (افق ۶) مثبت و با هزینهٔ ۰.۳٪ هم مثبت
۳. در ≥ ۶۰٪ ماه‌ها مثبت ۴. دنبالهٔ چپ کنترل‌شده ۵. در ≥ ۶۰٪ نمادها مثبت
۶. نیمهٔ دوم داده هم مثبت

علاوه بر این، گزارش همیشه **اختلاف با خط پایه** را هم می‌آورد: میانهٔ بازده
همهٔ کندل‌های بازار در همان افق. اگر رویداد از خط پایه بهتر نباشد، هر عدد مثبتی
فقط «روند بازار» است، نه لبهٔ پامپ.

### چطور گزارش را بخوانی

| بخش | چه می‌گوید |
|---|---|
| شمارش | رویداد خام در برابر **رویداد مستقل** — اختلاف زیاد یعنی خوشه‌بندی |
| جدول افق‌ها | میانه/میانگین/چارک‌ها/نرخ برد/بدترین ۵٪ |
| حساسیت هزینه | همان عدد با ۰.۰۵٪ / ۰.۱۵٪ / ۰.۳٪ |
| خط پایه | «همهٔ کندل‌ها» در همان افق |
| دروازه | شش شرط، ✅/❌ |

## ۳.۲۰) چشم شکارچی — زمینهٔ سیگنال‌ها و مقایسهٔ برد و باخت

### این چه چیزی را حل می‌کند

تا حالا فقط می‌دانستیم «این معامله برد/باخت». از این به بعد هر سیگنال **۱۸
ویژگی آن لحظه** را با خودش ثبت می‌کند (نوسان، ADX، RSI، حجم غیرعادی، شیب EMA،
جایگاه در کانال، گپ، ساعت روز، رشتهٔ برد/باخت اخیر، و **هزینهٔ رفت‌وبرگشت ÷
ATR**). بعد ابزار `hunter` می‌گوید در کدام زمینه‌ها بردها از باخت‌ها جدا بودند.

### چرخهٔ کامل (روی گوشی یا کامپیوتر)

```bash
# ۱) یک دور اتوترید مجازی با بازسازی گذشته (ژورنال با زمینه پر می‌شود)

# ۲) گزارش چشم شکارچی
bash run-auto.sh --hunt

# ۳) سلامت مکانیکی معاملات
bash run-auto.sh --audit
```

خروجی `hunter`: `results/hunter_fa.md` — کپی خودکار به Download.

### سه محافظی که در گزارش هست

| محافظ | چه می‌کند |
|---|---|
| AUC به‌جای میانگین | ۰.۵ = بی‌تفاوت؛ مقاوم به دادهٔ پرت |
| آزمون جایگشتی | p بدون فرض توزیع |
| بونفرونی + حداقل بزرگی اثر | ۱۸ ویژگی = ۱۸ آزمون؛ آستانه از ۰.۰۵ به ~۰.۰۰۳ سخت می‌شود |
| تأیید بیرون‌نمونه | همان جهت اثر باید در ۴۰٪ آخر داده هم دیده شود |

حکم «قابل بررسی» یعنی **نامزد برای آزمایش در آزمایشگاه**، نه «اعمال کن».
این ابزار هیچ پارامتری را خودش عوض نمی‌کند.

### اگر ژورنال قدیمی باشد

ژورنال‌های قبل از این نسخه `context` ندارند. برنامه خودش می‌گوید. کافی است یک
دور `--live` تازه بزنی. ژورنال قدیمی را پاک نکن؛ اسمش را عوض کن
(`mv results/live/journal.jsonl results/live/journal_old.jsonl`).

| `bash run-auto.sh --bundle` | ساخت بستهٔ مستقل موتور |

## ۳.۲۲) شکار زنده + هشدار + حسابرسی خروج (تب‌های تازهٔ داشبورد)

### چهار چیزی که اضافه شد

| تازه | چه می‌کند | دستور |
|---|---|---|
| **شکار زنده** | برای هر نماد: چه شرطی پاس است، چه شرطی نه، **وزن آمادگی** | `bash run-auto.sh --watch` |
| **هشدار** | بوق + اعلان Termux وقتی نمادی «نزدیک» شد | خودکار داخل `--watch` |
| **حسابرسی خروج** | چقدر سود با بستن زودهنگام ریخت (MFE در برابر نتیجه) | `bash run-auto.sh --exits` |
| **دو تب داشبورد** | «شکار زنده» و «خروج زودهنگام» با جستجو/فیلتر/مرتب‌سازی | `bash run-auto.sh --dash` |

### وزن آمادگی چطور حساب می‌شود

هفت شرط، هر کدام با وزن **از پیش ثابت** (جمع = ۱۰۰):

| شرط | وزن | معنی |
|---|---:|---|
| دادهٔ لایه‌ها | ۵ | هر دو لایه کندل بسته دارند |
| هم‌جهتی بایاس | ۲۰ | جهت کلان با تریگر هم‌جهت است |
| هم‌جهتی فیلتر | ۲۰ | رژیم/جهت لایهٔ میانی |
| تریگر | ۲۵ | pullback یا breakout برقرار است |
| حرکت به‌اندازهٔ هزینه | ۱۲ | حرکت مورد انتظار ≥ ۱.۵× هزینه |
| امتیاز اعتماد | ۱۰ | از آستانهٔ `min_confidence` |
| کندل اوج نبودن | ۸ | دامنه ≤ سقف (نَدویم دنبال قیمت) |

**مهم:** این وزن از همان `bias_state` / `filter_state` / `trigger_state` /
`decide` می‌آید که موتور واقعاً اجرا می‌کند. هیچ امتیاز موازی ساخته نشده؛ وگرنه
داشبورد چیزی نشان می‌داد و موتور چیز دیگری معامله می‌کرد.

سه حالت: **سیگنال** (موتور الان وارد می‌شود) · **نزدیک** (وزن ≥ ۷۵٪ یا فقط یک
شرط مانده) · **دور**.

### هشدار

```bash
bash run-auto.sh --watch         # یک‌بار (برای دیدن)
bash run-auto.sh --watch-loop    # هر ۵ دقیقه تا Ctrl+C
```

- بوق ترمینال + اعلان نوار اعلان (اگر `termux-api` نصب باشد).
- **ضدتکرار**: یک نماد در یک سطح، حداکثر هر ۳۰ دقیقه یک‌بار (`--cooldown-min`).
- خاموش‌کردن هر کدام: `--no-beep` / `--no-notify`.
- پیمایش داخل کندل است ⇒ در گزارش صریح `intra_candle` می‌خورد. **تصمیم** فقط روی
  کندل بسته گرفته می‌شود؛ این ابزار تصمیم نمی‌گیرد.

### حسابرسی خروج — همان «زود بسته شد»

```bash
bash run-auto.sh --exits
```

برای هر معامله: بیشترین سود شناور (`mfe_pct`) ÷ ریسک = **MFE به واحد R**، و
«سودِ ریخته‌شده» = MFE − نتیجه. چهار دسته:

| دسته | معنی |
|---|---|
| برندهٔ پس‌داده‌شده | در سود بود، سربه‌سر/ضرر بست |
| کوتاه‌شده | سود گرفت ولی ≥۱R روی میز ماند |
| خوب | نزدیک سقف بست |
| حد ضرر سالم | هرگز سود نشد؛ استاپ کارش را کرد |

آخر گزارش، «نامزدهای آزمایشگاه» می‌آید (`trail_start_r`، `breakeven_at_r`،
`max_holding_bars`) — **نامزد، نه تغییر خودکار**.

### داشبورد

`bash run-auto.sh --dash` → دو تب تازه:

- **شکار زنده**: نوار آمادگی هر نماد، جستجوی نماد، فیلتر حالت، مرتب‌سازی
  (آمادگی/نماد/تعداد شرط مانده). روی ردیف بزن ⇒ جدول شرط‌ها با مقدار و آستانه.
- **خروج زودهنگام**: کارت‌های خلاصه + جدول معاملات با جستجو و فیلتر دسته.

اگر «شکار زنده» را اجرا نکرده باشی، تب می‌گوید چه دستوری بزنی.

## ۳.۲۳) V10 Pro — سناریوی جداگانه کنار الگوهای خودمان

این همان «Bybit Quant Trading Engine V10 Pro» است که فرستادی: **بازگشت به میانگین**
روی ۱۵ دقیقه، در هر دو جهت، فقط کاغذی (PAPER). عمداً **جدا** گذاشته شد تا با
الگوهای خودمان روی **همان داده و همان هزینه** مقایسه شود.

### سه دستور

```bash
cd my_project/apps/futures-mtf-lab

# ۱) دانلود یک‌بارهٔ داده (اگر کش نداری)
python3 -m mtflab v10 --download --days 180

# ۲) بک‌تست + فهرست نزدیکی + مقایسه با الگوهای MTF

# ۳) یا از راه میان‌بر

```

خروجی‌ها در `results/`:

| فایل | چیست |
|---|---|
| `v10_report.md` | گزارش خوانا (سنجه‌ها، دلیل بسته‌شدن‌ها، آزمون فرض ورود) |
| `v10_report.json` | همان، ماشین‌خوان |
| `v10_proximity.json` | امتیاز نزدیکی هر نماد به سیگنال (بدون سیگنال‌سازی الکی) |
| `v10_vs_mtf.json` | مقایسهٔ V10 Pro با الگوی MTF |

**تب داشبورد:** بعد از اجرا، `bash run-auto.sh --dash` → تب **V10 Pro**
(کارت سنجه‌ها، نوار نزدیکی هر نماد، آخرین ۲۰ معامله).

### قاعده‌ها — دقیقاً همان چیزی که در پروپوزال بود

| شرط | مقدار |
|---|---|
| باند بولینگر | ۲۰ / ۲.۰ |
| کندل قبل بیرون باند، کندل فعلی برگشته داخل | لازم |
| کندل بازگشتی هم‌جهت (بدنهٔ صعودی/نزولی) | لازم |
| RSI کندل قبل | ≤ ۳۰ برای خرید، ≥ ۷۰ برای فروش |
| حجم | ≥ ۱.۳۵ × میانگین ۲۰ کندل |
| پاداش مورد انتظار | ≥ ۰.۳۵٪ |
| حد ضرر | پایین/بالای الگو ∓ ۰.۱×ATR(14) |
| حد سود | ۲.۵R |
| سپر سربه‌سر | در ۱R |
| خروج پویا | برگشت به باند میانی |
| سقف زمان | ۱۶ کندل |
| هزینه | کارمزد ۰.۰۵۵٪ + اسلیپیج ۰.۰۲٪ هر طرف |

### سه جا که عمداً با پروپوزال فرق دارد (و چرا)

1. **ورود:** پیش‌فرض ورود در **باز شدن کندل بعد** است، نه در بستهٔ همان کندل.
   الگو فقط در بستهٔ کندل معلوم می‌شود؛ ورود در همان بسته یعنی معامله با قیمتی که
   دیگر وجود ندارد. حالت پروپوزال با `--entry close` هم اجرا و **کنار هم** گزارش
   می‌شود، تا خودت تفاوت را ببینی.
2. **روباری هم‌کندل:** اگر یک کندل هم حد ضرر و هم حد سود را لمس کند، پیش‌فرض
   «اول حد ضرر» است. حالت خوش‌بین: `--same-bar optimistic`.
3. **هزینه:** همیشه کم می‌شود و ستون «سهم هزینه» جدا گزارش می‌شود.

### چطور گزارش را بخوانی

- **expectancy R** = میانگین سود/ضرر هر معامله به واحد ریسک. مثبت = لبه، منفی = ضرر.
- **ضریب سود** = سود کل ÷ ضرر کل. زیر ۱ = ضررده.
- **با چه قاعده‌ای بسته شدند** = مشخص می‌کند استاپ می‌خوردیم یا حد سود/زمان.
- **آزمون فرض ورود** = اگر `close` خیلی بهتر از `next_open` باشد، بخشی از سود
  پروپوزال از فرض ورود آمده، نه از لبه.
- **اگر خروج باند میانی را برداریم** = همان بحث «خروج‌هایی که سود را می‌کشند»:
  با یک کلید (`bb_mid_exit`) هر دو حالت روی همان داده اجرا و مقایسه می‌شوند.

### صداقت — چیزی که نباید از دست برود

- اعداد پروپوزال (OOS +۰.۶۵٪، شارپ ۱.۲۵، ۵۰–۷۵٪ برد) **ادعای تأییدنشده** است؛
  در گزارش هم همین‌طور برچسب می‌خورد.
- خط «داده:» بالای گزارش می‌گوید کندل‌ها از کجا آمده‌اند و چه بازه‌ای را پوشش
  می‌دهند. اگر «منبع برچسب ندارد» دیدی، یعنی داده دست‌ساز/آزمایشی است — نتیجه‌اش
  دربارهٔ بازار **هیچ** حکمی نمی‌دهد.
- این ابزار سفارش نمی‌فرستد. PAPER.

## ۳.۲۴) «این سیگنال بابت کدام الگو بود؟» + حذف الگوی بی‌فایده

تا حالا هر سیگنال یک الگو داشت، ولی معلوم نبود روی همان کندل **چه الگوهای دیگری**
هم تأییدش می‌کردند. حالا هر سیگنال این را با خودش می‌برد و یک کارنامه از همه
می‌سازیم.

### چهار دستور

```bash
cd my_project/apps/futures-mtf-lab

bash run-auto.sh --live            # هر سیگنال، همان لحظه می‌گوید بابت چه الگوهایی بود
bash run-auto.sh --patterns        # کارنامه: کدام الگو سود داد، کدام نه + پیشنهاد حذف
bash run-auto.sh --v10 --compare   # مقایسهٔ سناریوی V10 با الگوهای MTF
bash run-auto.sh --v10 --archive   # بایگانی فورنزیک سیگنال‌های V10
```

### موقع سیگنال چه می‌بینی

```
   ⚡ BTCUSDT LONG @ 30234.21 · الگوها: base, pullback (هم‌گرا)
```

- **الگوها** = همهٔ الگوهایی که روی همان کندل شرط ورودشان برقرار بود.
- **(هم‌گرا)** = بیش از یک الگو تأیید کرد.
- همین فهرست در ژورنال (`results/live/journal.jsonl`) زیر کلید `pattern_votes`
  ذخیره می‌شود؛ پس بعداً هم قابل حسابرسی است.
- رأی = **شرط‌های ورودِ الگو**، نه «اسلات آزاد بود». اگر اشغال اسلات یا کول‌داون
  جلوی معامله را بگیرد، ربطی به خوب/بد بودن الگو ندارد و در رأی شمرده نمی‌شود.
- خاموش‌کردن (سریع‌تر): `--no-votes`.

### کارنامهٔ الگوها — عدد، نه حس

```bash
bash run-auto.sh --patterns
# یا برای ژورنال دلخواه:
python3 -m mtflab patterns --journal results/live/journal.jsonl
```

خروجی `results/pattern_scorecard.md` و `.json`، با سه جدول:

| جدول | چه می‌گوید |
|---|---|
| الگویی که سیگنال را ساخت | برای هر الگو: تعداد، نرخ برد، expectancy R، ضریب سود |
| رأی الگوها روی همان کندل | برای هر الگو: وقتی حاضر بود چطور شد، **تنها** چطور، **با تأیید دیگران** چطور |
| آیا تأیید چند الگو ارزش داشت؟ | expectancy سیگنال‌های هم‌گرا در برابر تک‌الگو |

### قاعدهٔ حذف (از قبل نوشته شده)

| شرط | حکم |
|---|---|
| n < ۳۰ | **داده کافی نیست** — هیچ حذفی نمی‌شود |
| n ≥ ۳۰ و expectancy > ۰ | **نگه‌دار** |
| n ≥ ۳۰ و expectancy ≤ ۰ | **نامزد حذف** |

این قاعده بعد از دیدن نتیجه عوض نمی‌شود. هیچ الگویی خودکار حذف نمی‌شود؛ فهرست
`keep / drop / need_more` پیشنهاد است و تصمیم با توست.

### تنظیمات پروپوزال (V9)

فایل `config/v10_settings.json` با همان کلیدهای خودت ساخته شد (`v9_parameters`،
`fee_rate`، `round_trip_cost_pct`، …). `python3 -m mtflab v10` خودش آن را می‌خواند؛
اگر کلیدی ناشناس باشد، در خروجی `ignored` گزارش می‌شود، بی‌صدا دور ریخته نمی‌شود.
`min_reward_filter_pct` کسری (۰.۰۰۳۵) به درصد (۰.۳۵) تبدیل می‌شود.


هر فایل: سیگنال، چهار جزء قاعده با **مقدار واقعی** (باند، RSI، نسبت حجم، کندل
بازگشتی)، پارامترهای همان لحظه، و ۵ کندل آخر. با این شواهد می‌شود شرطی مثل «جهش

## ۳.۲۵) هر سیگنال، یک پروندهٔ کامل + سیگنال دستی + کاتالوگ الگوریتم‌ها

سه چیزی که کم بود و اضافه شد: (۱) خودِ اعداد لحظهٔ ورود و لحظهٔ خروج در ژورنال
ذخیره و در داشبورد دیده شوند، (۲) هر الگوریتم با فرمول و **مقدار فعلی** داخل یک
جعبه توضیح داده شود، (۳) وقتی اعتبارسنجی کامل نیست، خودت بتوانی یک سیگنال
(کاغذی) بگیری.

### ۱) در ژورنال چه ذخیره می‌شود

هر سیگنال دو لحظه دارد و **هر دو** ثبت می‌شوند، نه فقط نتیجه:

| لحظهٔ ورود (`type:"open"`) | لحظهٔ خروج (`type:"close"`) |
|---|---|
| `entry_candle` (O/H/L/C/حجم کندل ورود) | `exit_candle` (O/H/L/C/حجم کندل خروج) |
| `order.stop` و `order.take` (حد ضرر/حد سود) | `order.stop_initial` و `order.stop_final` |
| `order.fee_open` (کارمزد ورود) | `result.fee_close` (کارمزد خروج) |
| `entry_indicators` + `entry_context` | `exit_indicators` + `exit_context` |
| `pattern_votes` + `origin` (`auto`/`manual`) | `closed_by` (قاعده‌ای که بست) + `diagnosis` |
| — | `result`: `pnl`, `fees`, `r_multiple`, `mfe_pct`, `mae_pct`, `bars_held` |

- `closed_by` همیشه یکی از این‌هاست: `stop`, `take`, `trail`, `time_stop`,
  `breakeven`, `regime_flip`, `partial` … و در جدول داشبورد زیر ستون «بست با»
  دیده می‌شود.
- اگر رکورد قدیمی (قبل از این نسخه) باشد، داشبورد به‌جای عدد **«ثبت نشده»**
  نشان می‌دهد. هیچ عددی از خودمان نمی‌سازیم.

### ۲) در داشبورد کجا را نگاه کنی

```bash
bash run-auto.sh --dash        # http://127.0.0.1:8770/
```

تب **سیگنال‌ها**:

- بالای صفحه یک نوار وضعیت: چند معامله، expectancy، بیرون‌نمونه، و اینکه
  «اعتبارسنجی کامل است یا ناقص».
- دکمهٔ **🎯 گرفتن سیگنال دستی** — همان موتور و همان قواعد را یک‌بار روی آخرین
  کندل اجرا می‌کند و اگر شرط‌ها برقرار باشند یک سیگنال کاغذی واقعی ثبت می‌شود
  (`origin: "manual"`). اگر شرط‌ها برقرار نباشند، صادقانه می‌گوید «سیگنالی نبود».
  در حالت `--demo` این دکمه کار نمی‌کند (چون داده‌اش ساختگی است).
- جدول: شناسه، نماد، کندل ورود، الگو (+ نشان هم‌گرا)، ورود، حد ضرر، حد سود،
  کارمزد، R، سود، وضعیت، بست با، کندل خروج.
- روی هر ردیف بزن: پروندهٔ کامل باز می‌شود — دو جعبهٔ کندل (ورود/خروج)،
  سفارش و ریسک با تفکیک کارمزد، اندیکاتورهای ورود، اندیکاتورهای خروج

تب **الگوریتم‌ها** (تب دهم):


- ۴ بخش / ۱۷ مورد: پنج الگوی MTF، V10 Pro، قواعد خروج (حد ضرر/سقف زمانی/
  سربه‌سر/تریل/برداشت جزئی)، و پامپ و دامپ.
- برای هر الگوریتم یک جعبه با **فرمول** و زیرش خط **مقادیر فعلی** — همان اعدادی
  که الان در `MTFConfig`، `v10_settings.json` و `rules.RULE_META` هستند، نه
  اعداد دستیِ کپی‌شده. اگر پارامتری را عوض کنی، این صفحه خودش عوض می‌شود.
- آستانه‌های صفر به‌صورت «خاموش / بی‌سقف / بدون TP» نمایش داده می‌شوند تا با
  قاعدهٔ واقعی اشتباه گرفته نشوند.
- در داشبورد یک کادر جستجو دارد؛ تایپ کن «حد ضرر» یا «RSI» تا فقط همان‌ها بمانند.

### ۳) تذکر

سیگنال دستی هم **کاغذی** است و از همان مسیر عادی می‌گذرد (کارمزد، ریسک،
اسلات، کول‌داون). چیزی به آمار اضافه نمی‌کند جز یک معاملهٔ واقعیِ ثبت‌شده.

## ۳.۲۶) دفتر خبر — «آن منبع سیگنال چقدر معتبر بود؟»

خبر که می‌آید بازار زیر و رو می‌شود و آدم می‌خواهد همان لحظه یک سیگنال بزند و
بعد بفهمد «آن منبع» راست می‌گفت یا نه. این کار با اتوترید معمولی فرق دارد
(آن‌جا منتظر بسته‌شدن کندل و جور شدن شرط‌ها می‌مانیم)، پس یک دفتر **جدا** ساخته
شد: `results/live/shadow.jsonl`.

**سه قانون این دفتر:**

1. **جهت را خودت می‌زنی**: دکمهٔ BUY یا SELL. اگر موتور همان لحظه سیگنالی
   نداشت، بازهم ثبت می‌شود (برچسب «خبری»).
2. **روی سیستم اثر ندارد**: نه سرمایهٔ خیالی را کم می‌کند، نه اسلات می‌گیرد،
   نه در `journal.jsonl` می‌نشیند، نه در آمار/اعتبارسنجی/کارنامهٔ الگوها.
   تست خودکار همین را تضمین می‌کند.
3. **خروج خودکار با همان تنظیمات**: حد ضرر (۱.۵×ATR)، حد سود (اگر روشن باشد)،
   تریل، سربه‌سر، سقف زمانی، و کارمزد + اسلیپیج. اگر در یک کندل هم حد ضرر و هم
   حد سود لمس شود، **حد ضرر** فرض می‌شود (بدبینانه‌ترین حالت).

### در داشبورد

```bash
bash run-auto.sh --dash
```

تب **دفتر خبر** (کنار تب سیگنال‌ها):

- نماد را انتخاب کن، یادداشت خبر را بنویس (مثلاً «تصویب ETF»)، بعد **🟢 BUY**
  یا **🔴 SELL** را بزن. همان لحظه ثبت می‌شود.
- قیمت: اگر اینترنت باشد **آخرین قیمت معاملهٔ بازار** (تیکر عمومی Bybit)؛ اگر
  نباشد **بستهٔ آخرین کندل** — و در پرونده نوشته می‌شود کدام یکی بوده
  (`price_source`: `ticker` یا `last_close`). هیچ عددی جعل نمی‌شود.
- زیرش «کارنامهٔ اعتبار منبع» می‌آید: n، نرخ برد، expectancy (R)، و حکم
  (منبع معتبر / بی‌اعتبار / داده کافی نیست) — هم کل، هم به تفکیک الگویی که
  **همان لحظه** رأی داده بود، هم هم‌جهت/خلافِ بایاس تایم‌فریم بالا.
- ستون «منبع (رأی)» نشان می‌دهد در آن لحظه کدام الگوها شرط ورود داشتند؛
  «—» یعنی هیچ‌کدام (که برای سیگنال خبری طبیعی است).
- دکمهٔ «بستن دستی» هم هست، اگر خواستی خودت دفتر را ببندی.

### با دستور

```bash
bash run-auto.sh --shadow                     # کارنامه + فهرست
python3 -m mtflab shadow --json                # همان + results/shadow_book.json

# ثبت سیگنال خبری از خط فرمان (بدون شبکه: --offline)
python3 -m mtflab shadow --open BTCUSDT --side LONG --note "خبر ETF" --offline

# روی گوشی با اینترنت، قیمت لحظه‌ای هم گرفته می‌شود (بدون --offline)
python3 -m mtflab shadow --open BTCUSDT --side SHORT --note "هک صرافی"
```

### تذکرهای صادقانه

- خروجی که **شبیه‌سازی نمی‌شود**: «برگشت رژیم» و «سیگنال مخالف» — چون به وضعیت
  کامل لایه‌ها وابسته‌اند. پس عدد R این دفتر دقیقاً همان عدد اتوترید نیست؛
  برای سنجش اعتبار منبع است، نه جای کارنامهٔ اصلی.
- با n کم هیچ حکمی نمی‌دهیم (آستانه ۱۰ برای دفتر خبر، ۳۰ برای اعتبارسنجی اصلی).
- در حالت `--demo` (دادهٔ مصنوعی) این دکمه کار نمی‌کند.

## ۳.۲۷) سؤال «ثابت درصدی یا شناور؟» — با آزمایش، نه سلیقه

سؤال: روی همان دادهٔ یک‌ساله، حد ضرر/سود **ثابت درصدی** بهتر است یا **شناور
(ATR + تریل)**؟

```bash
cd my_project/apps/futures-mtf-lab
bash run-auto.sh --exit-styles
# یا با کنترل کامل:
python3 -m mtflab exitstyles --data-dir data --tf auto --variant base
```

خروجی: `results/exit_styles_<tf>_<تاریخ>.md` و `.json`.

### چرا نمی‌شود با «دو بک‌تست معمولی» جواب داد

در بک‌تست معمولی، تغییر حد ضرر **نتیجهٔ ورودها** را هم عوض می‌کند (کول‌داون،
اشغال اسلات، تعداد معامله). آن‌وقت معلوم نیست تفاوت از «خروج» آمده یا از
«چند معامله شدن». این ابزار برای همین سه کار می‌کند:

1. دروازهٔ ورود موتور روی هر کندل **یک‌بار** حساب می‌شود.
2. همان فهرست ورود به **همهٔ سیاست‌ها** داده می‌شود.
3. هر سیاست در **دو حالت** اجرا می‌شود:
   - **واقع‌گرا**: هر بار یک پوزیشن (مثل سیستم) — n می‌تواند بین سیاست‌ها فرق کند.
   - **مستقل**: همهٔ ورودی‌ها جدا شبیه‌سازی می‌شوند — n یکسان، مقایسهٔ خالص خروج.

### سیاست‌هایی که مقایسه می‌شوند

| سیاست | یعنی |
|---|---|
| ثابت ۱٪ / ۲٪ · ۱.۵٪ / ۳٪ · ۲٪ / ۴٪ · ۳٪ / ۶٪ | حد ضرر و حد سود درصدی، بدون تریل |
| شناور ATR ۱.۵ / ۳ + تریل ۲ | همان تنظیم فعلی سیستم (خط پایه) |
| شناور ATR ۲ / ۴ + تریل ۲.۵ | شناور بازتر |
| شناور ATR ۱.۵ بدون حد سود + تریل ۳ | «بگذار بدود» |
| **ثابت هم‌عرض ATR×۱.۵ / ۲R** | همان عرض حد ضرر شناور، ولی درصدی و بدون تریل — منصفانه‌ترین مقایسه |

آن ردیف آخر مهم است: اگر «ثابت ۲٪» را با «شناور ۰.۷٪» مقایسه کنی، در واقع
«حد ضرر باز در برابر تنگ» را مقایسه کرده‌ای، نه «ثابت در برابر شناور».

### چطور بخوانی (و چطور گول نخوری)

- ستون اصلی **expectancy R** است، نه نرخ برد. حد ضرر بازتر همیشه نرخ برد را
  بالا می‌برد و همیشه هم سود بیشتری نمی‌دهد.
- ستون **حد ضرر ٪** عرض واقعی را نشان می‌دهد؛ اگر دو ردیف عرضشان فرق دارد،
  مقایسه‌شان منصفانه نیست.
- **R** ریسک‌نرمال‌شده است (۱٪ سرمایه در هر معامله)؛ درصد خام گمراه‌کننده است.
- حکم فقط با `n ≥ ۳۰` + **تأیید بیرون‌نمونه (۳۰٪ آخر)** + **تأیید حالت مستقل**
  صادر می‌شود. وگرنه «تفکیک‌نشده» / «داده کافی نیست».
- کارمزد و اسلیپیج هر دو طرف حساب می‌شوند (`--fee-bps`, `--slippage-pct` در
  پیکربندی). بدون آن، حد ضرر تنگ به‌طور مصنوعی برنده می‌شود.

### داده لازم

فایل‌های کش‌شده در `data/json/` با همان تایم‌فریمی که داری (مثلاً `*_1h.json`).
`--tf auto` پرتکرارترین را انتخاب می‌کند و فیلتر/بایاس را از همان می‌سازد.
اگر داده نبود، دستور خودش می‌گوید اول `--download` بزن.

## ۳.۲۸) «مدیریت کلان» — دادهٔ واقعی و آزمون‌ها، از داخل داشبورد

تب تازه‌ای اضافه شد که کارهایی را که قبلاً فقط با دستور ممکن بود، از خودِ
داشبورد اجرا می‌کند — و همه در **پس‌زمینه**، تا صفحه قفل نشود.

### در داشبورد

```bash
bash run-auto.sh --dash     # تب «مدیریت کلان»
```

| دکمه | چه می‌کند |
|---|---|
| 🌐 **بررسی دسترسی به داده** | تست واقعی Bybit (کندل، نه پینگ). اگر فیلتر باشی، صریح می‌گوید |
| ♻️ **به‌روزرسانی داده (۳۰ روز)** | کندل‌های تازه را می‌گیرد و با کش **ادغام** می‌کند (تاریخ قبلی پاک نمی‌شود) |
| ⬇️ **دانلود یک‌ساله** | ۴ نماد × ۳ تایم‌فریم (۱ساعته/۴ساعته/روزانه) → `data/json/*.json` |
| 🧪 **آزمایش خروج (ثابت/شناور)** | همان آزمایش `exitstyles`؛ گزارش در `results/ops/` |
| 🩺 **معاینهٔ نصب** | همان `doctor`: پورت، داده، پوشه‌ها، termux-api |

زیرش دو بخش دارد:

- **کارها**: وضعیت هر اجرا (در حال اجرا / تمام / خطا)، مدت، خلاصه و لاگ کامل.
- **گزارش‌های مستقل**: هر اجرا یک فایل جدا در `results/ops/`؛ روی نامش بزن،
  همان‌جا باز می‌شود.

### سه قاعده‌ای که رعایت شده

1. **صفحه قفل نمی‌شود**: سرور داشبورد تک‌رشته‌ای است؛ دانلود یک‌ساله اگر همگام
   اجرا شود مرورگر دقیقه‌ها منتظر می‌ماند. پس هر کار در نخ جدا اجرا می‌شود و UI
   هر ۲.۵ ثانیه وضعیت را می‌پرسد.
2. **گزارش مستقل**: هیچ آزمونی در `journal.jsonl`، سرمایه، اعتبارسنجی یا
   کارنامهٔ الگوها نمی‌نویسد. یک تست خودکار همین را تضمین می‌کند.
3. **بدون ادعا**: اگر شبکه نبود، کار با خطای صریح تمام می‌شود و **کش قبلی
   دست‌نخورده** می‌ماند (تست هش فایل را قبل/بعد مقایسه می‌کند). هیچ داده‌ای
   جعل نمی‌شود و «موفق» اعلام نمی‌شود.

### همان کارها با دستور (برای اسکریپت/کران)

```bash
bash run-auto.sh --ops                        # وضعیت داده و گزارش‌ها
bash run-auto.sh --ops --probe                # تست دسترسی به دادهٔ بازار
bash run-auto.sh --ops --sync                 # به‌روزرسانی ۳۰ روز اخیر (ادغام)
bash run-auto.sh --ops --download --days 365  # دانلود یک‌ساله
bash run-auto.sh --ops --exitstyles           # آزمایش خروج (گزارش مستقل)
bash run-auto.sh --ops --doctor               # معاینهٔ نصب
```

### نکتهٔ مهم دربارهٔ «اینترنت حقیقی»

- تا وقتی دکمهٔ دانلود/به‌روزرسانی را نزنی، داشبورد از همان کش محلی می‌خواند.
- دانلود فقط **کندل بسته** می‌گیرد (بدون API key، فقط endpoint عمومی).
- اگر IP تو برای دادهٔ Bybit فیلتر باشد، «بررسی دسترسی» همان را نشان می‌دهد؛
  در آن حالت VPN/آینه لازم است و برنامه چیزی از خودش نمی‌سازد.

## ۴) قاعدهٔ پذیرش — از قبل تعیین شده

این قاعده **قبل از دیدن نتیجه** نوشته شده و بعد از دیدن نتیجه تغییر نمی‌کند.
یک نسخه فقط وقتی «قبول» است که **همهٔ** این‌ها را داشته باشد:

| شرط | حد |
|---|---|
| تعداد نماد با دادهٔ کافی | ≥ ۸ |
| نمادهای با PF>1 | ≥ ۶۰٪ |
| سال‌های مثبت | ≥ ۶۰٪ |
| میانهٔ PF | ≥ ۱.۰۵ |
| معناداری در برابر نسخهٔ پایه | p ≤ ۰.۱۰ |
| حداقل معامله | ≥ ۱۰۰ |

اگر هیچ نسخه‌ای قبول نشد، **این هم یک نتیجه است** — و همان را می‌نویسیم.
فهرست ۲۰ نماد هم داخل کد ثابت است تا بعد از دیدن نتیجه عوضش نکنیم.

## ۳۹) «سیستم کار می‌کند ولی سیگنالی نیست» — کارت سلامت + ساعتِ بازار

سؤال درست همین است: «سکوت» با «خرابی» یکی نیست. حالا هر دو جای مشخص و عددی دارند.

### ۳۹.۱) کارت «سلامت سیستم» (بالای تب **زنده**)

بالای تب زنده یک کارت اضافه شده که هر ثانیه خودش را به‌روز می‌کند و **چهار چیز** را
ثابت می‌کند، نه اینکه بگوید «خبری نیست»:

| ستون | چه چیزی را ثابت می‌کند |
|---|---|
| **زمان** | آخرین کندلِ **بستهٔ** هر تایم‌فریم + شمارش معکوس تا بستهٔ بعدی (`04:00:00` یعنی تا ۴ ساعت دیگر ارزیابی می‌شود) |
| **تازگی داده** | «چند کندل عقب» — اگر ۰ باشد، کش با ساعت هم‌گام است؛ اگر ۱۷۶۰۱ باشد، داده کهنه است و سیستم **خودش** می‌گوید |
| **گرم‌شدن** | هر لایه (تریگر EMA/ATR/RSI/Donchian/حجم، فیلتر EMA/ADX، بایاس EMA200/Donchian/شیب) با `دارم/لازم` — مثلاً `1600/50 ✅` |
| **دروازه‌ها** | هفت شرط ورود، هرکدام با «رد شد/چرا» — یعنی می‌بینی کدام شرط جلوی سیگنال را گرفته |

بالای کارت یک حکم کوتاه است: **`سالم است؛ منتظر کندل بعدی`**، `سالم است؛ نزدیک ورود`،
`سیگنال تازه`، `داده کهنه است`، `در حال گرم شدن`، `داده‌ای نیست`.

ترتیب اولویت حکم (اولی که برقرار شود، همان نمایش داده می‌شود):
`داده‌ای نیست → داده کهنه → گرم‌شدن → سیگنال → نزدیک ورود → منتظر کندل`.

### ۳۹.۲) از ترمینال (همان عددها، بدون داشبورد)

```bash
bash run-auto.sh --health
# یا با مسیر و تایم‌فریم دلخواه:
python3 -m mtflab health --data-dir data --tf 1h --tf-filter 4h --tf-bias 4h
python3 -m mtflab health --json          # برای اسکریپت/مقایسه
```

مثال واقعی از حالتِ خراب (ساعت سیستم جلو/داده قدیمی) — خودش خطا را می‌گوید:

```
داده کهنه است — 17601 کندل عقب
| نماد | آخرین کندل | عقب | گرم‌شدن | دروازهٔ اولِ بسته |
```

و در حالت سالم:

```
سالم است؛ منتظر کندل بعدی — همهٔ لایه‌ها آماده‌اند و دروازه‌ها کار می‌کنند،
ولی شرط ورود برقرار نیست. ارزیابی بعدی: 2026-11-17T08:00:00Z
```

اگر «داده‌ای نیست» دیدی یعنی هیچ فایل کشی نبوده (کد ۲) — با `--ops --sync` یا
`--ops --download` اول داده بگیر.

### ۳۹.۳) «ساعت باز شدن بازار» در فیوچرز یعنی چه؟

- فیوچرز (پرپتوال کریپتو) **۲۴/۷** است؛ «باز شدن» و «بسته شدن» ندارد. پس ساعتِ
  بورس‌های سنتی، ورود را قفل نمی‌کند.
- آن‌چه واقعاً مهم است **مرز کندل** است: سیستم ۴ ساعته فقط در `00/04/08/12/16/20 UTC`
  ارزیابی می‌کند. برای همین کارت سلامت شمارش معکوس تا همان لحظه را نشان می‌دهد.
- نشست‌های آسیا/لندن/نیویورک و آخر هفته فقط روی **نقدشوندگی** اثر دارند (اسپرد
  بازتر، شکست‌های کاذب بیشتر)؛ فیلتر کارمزد/ATR همان را جذب می‌کند، ولی به‌تنهایی
  «اجازهٔ ورود» نمی‌دهد.

### ۳۹.۴) پامپ و دامپ جدا از فیوچرز است

تب **پامپ و دامپ** (`mtflab/pumpdump.py`) یک سیستم مستقل با خروجی‌های خودش در
`results/` است؛ فقط **کش کندل** و **store** را با بقیه شریک است و هیچ‌وقت در
ژورنال/سرمایه/آمارِ فیوچرز نمی‌نویسد. کارت سلامت هم فقط وضعیت موتور فیوچرز را
می‌سنجد.

### ۴۰.۲) دستورِ اتوماتیک (یکی، همیشه همین)

از ریشهٔ `futures-mtf-lab`:

```bash

```

> **«ماند؟» نه — خودآزمایی ساکت است، نه خراب.** خط اول آن شناسنامه را چاپ می‌کند
> (`نسخه: … · کد: e6295bc · پایتون 3.13 · Termux`) و بعد تست‌های واحد شروع می‌شوند:
> روی گوشی چند دقیقه طول می‌کشد و هر ۳ ثانیه یک خط `… 45s · 120 خط خروجی` می‌آید.
> اگر عجله داری: `python3 -m mtflab selftest --quick` (۴ آزمون موتور، کمتر از ۲ ثانیه).
> نسخهٔ چاپ‌شده در خط اول را با آخرین کامیت مقایسه کن؛ اگر قدیمی بود، `--update`.

این چه می‌کند (به ترتیب، همه در یک اجرا):

| گام | چه چیزی | چرا |
|---|---|---|
| ۱ | `--ops --probe` | آیا IP تو به دادهٔ Bybit دسترسی دارد؟ (تست واقعی کندل) |
| ۲ | `--ops --sync` | ۳۰ روز آخر را با **ادغام** به کش اضافه می‌کند |
| ۳ | `--live --backfill 400` | موتور را تا آخرین کندل بسته می‌بَرد و ژورنال می‌سازد |
| ۴ | `--health` | ساعت کندل، تازگی، گرم‌شدن، دروازه‌ها |
| ۵ | `--control` | **گزارش کنترل** در `results/control/control_<زمان>.md` |
| ۶ | خط پایان | مسیر فایل + `sha256` |

اگر شبکه نداشتی، همین دستور را با `--offline` بزن؛ گام ۱ و ۲ رد می‌شوند و
بقیه روی کش موجود اجرا می‌شوند:

```bash
bash run-auto.sh --evaluate --offline
```

> **مهم‌ترین نکتهٔ دادهٔ واقعی:** گام ۲ به‌طور پیش‌فرض فقط **۳۰ روز** را
> به‌روزرسانی می‌کند. با ۳۰ روز، لایهٔ `bias` روی ۱d فقط ۳۰ کندل دارد و
> **۲۰۰ کندل** لازم دارد ⇒ حکم «تاریخ کافی نیست (warmup)». این خرابی نیست،
> سدِ درستِ سیستم است. برای عبور از آن، همان دستور را با تعداد روز بزن:
>
> ```bash
> bash run-auto.sh --evaluate --days 365     # دانلود یک‌ساله + بقیهٔ گام‌ها
>
> # با نمادهای مشخص (دروازه حداقل ۸ نماد می‌خواهد):
> bash run-auto.sh --evaluate --days 730 \
>   --symbols BTCUSDT,ETHUSDT,SOLUSDT,XRPUSDT,BNBUSDT,DOGEUSDT,ADAUSDT,LINKUSDT
> ```
>
> گزارش کنترل خودش می‌گوید چند روز کم داری: ردیف «گرم‌شدن لایه‌ها» دقیقاً
> می‌نویسد مثلاً «کمبود تاریخ: دست‌کم ۱۷۱ روز (پیشنهاد: --days 365)».

### ۴۰.۳) اگر خواستی گام‌به‌گام (برای دیدن خروجی هر بخش)

### ۴۰.۴) چه چیزی را برای من بفرستی؟

پس از `--control` چیزی شبیه این چاپ می‌شود:

```
📄 results/control/control_20261117T081500Z.md
🧾 results/control/control_20261117T081500Z.json
🔐 sha256(md) = 3f9c…
```

سه راه، هر کدام راحت‌تر بود:

1. **فایل `.md`** را بفرست (بهترین حالت — همهٔ عددها داخلش است).
2. متنش را ببین و اسکرین‌شات بگیر:
   `cat results/control/control_*.md | tail -60`
3. از داخل داشبورد: `bash run-auto.sh --dash` → تب **مدیریت کلان** →
   دکمهٔ **📋 گزارش کنترل (یک فایل)** → لینک «دریافت گزارش .md».

> اگر خیلی کوتاه می‌خواهی: خروجی `bash run-auto.sh --health` هم کافی است،
> ولی گزارش کنترل چک‌لیست کامل (داده، تازگی، پردازش، ژورنال، حساب، حکم) را
> یک‌جا دارد و در فایل `.json` هش sha256 هست تا معلوم شود دستکاری نشده.

### ۴۰.۵) چه چیزی گزارش **نمی‌کند**

- هیچ عددی نمی‌سازد و هیچ چیزی را حدس نمی‌زند: اگر داده نبود می‌نویسد
  «دادهٔ محلی نیست» (`no_data`) و کد خروج ۱ می‌دهد.
- در ژورنال، `state.json`، سرمایه یا آمار اعتبارسنجی **هیچ** نوشتنی ندارد؛
  فقط `results/control/` را می‌سازد.
- سودآوری را تأیید نمی‌کند؛ فقط می‌گوید سیستم سالم اجرا شده و چه چیزی
  جلوی سیگنال را گرفته است.

## ۴۱) گزارش اعتبارسنجی را چطور بخوانیم؟ (`--gate`)

گزارش اسکن (`results/auto_scan_*.md`) در آخر یک کلمه می‌دهد: `FAIL` یا `PASS`.
مشکل: `FAIL` می‌تواند «۴ نماد داشتی» باشد یا «استراتژی ضرر می‌دهد». این دو زمین
تا آسمان فرق دارند. دستور `--gate` همان گزارش را می‌خواند و **هر شرط را با عدد**
نشان می‌دهد:

```bash
bash run-auto.sh --gate
# یا با مسیر مشخص:
python3 -m mtflab gate results/auto_scan_year365.json
```

خروجی سه بخش دارد: (۱) جدول شرط‌ها برای هر نسخه، (۲) جزئیات بهترین نسخه
(واقعی / لازم / ✅❌ / توضیح)، (۳) «برای عبور چه لازم است» با عدد.

### یک نکتهٔ ریاضی که باید بدانی

دروازه می‌خواهد `p ≤ ۰٫۱۰` در آزمون علامت. کمینهٔ ممکن p با **n نماد** برابر
`۲ × ۰٫۵ⁿ` است:

| نماد | کمینهٔ p | یعنی |
|---:|---:|---|
| ۴ | ۰٫۱۲۵ | **رسیدن به p≤۰٫۱ ناممکن است** — نه اینکه نتیجه بد بود |
| ۸ | ۰٫۰۰۷۸ | شدنی |
| ۱۰ | ۰٫۰۰۲۰ | راحت‌تر |

پس اگر با ۴ نماد `FAIL` گرفتی، بخش «معناداری» را با همین توضیح می‌بینی؛
راه‌حل، **نماد بیشتر** است نه دست‌کاری آستانه.

### نمونهٔ واقعی (گزارش گوشی، ۴ نماد، ۳۶۵ روز)

```
| نسخه | معامله | میانهٔ PF | expectancy | وضعیت | شرط‌های ردشده |
| trend | 75 | 1.4719 | 3.7601 | ❌ رد | نماد، معامله، معناداری |
```

یعنی: میانهٔ PF خوب، ۳ از ۴ نماد سودده، فقط **اندازهٔ نمونه** کم است.
