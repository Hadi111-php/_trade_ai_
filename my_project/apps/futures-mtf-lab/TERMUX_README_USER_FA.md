# 📱 اجرای اسکن خودکار روی گوشی (Termux)

این تنها کاری است که باید روی گوشی انجام دهید. کل فرایند خودکار است:
دانلود داده → ذخیره در JSON → تحلیل → گزارش.

## ۰) نصب یک‌باره (فقط بار اول)

Termux را از **F-Droid** نصب کنید (نسخهٔ Play Store قدیمی است و مشکل دارد).

```bash
pkg update -y && pkg install python git -y
```

بعد پروژه را بگیرید. ⚠️ **حتماً با نام برنچ** — کد روی شاخهٔ `main` نیست:

```bash
git clone -b arena/444f3300-trade-ai --single-branch --depth 1 \
  https://github.com/Hadi111-php/_trade_ai_.git lab
cd lab
```

> اگر `git clone` بدون `-b` بزنید، پوشهٔ `futures-mtf-lab` اصلاً وجود ندارد.
> مخزن عمومی است، پس نام کاربری/توکن لازم نیست.
> `--depth 1` حجم دانلود را کم می‌کند (مناسب گوشی).

> هیچ `pip install` لازم نیست. تمام کد با کتابخانهٔ استاندارد پایتون نوشته شده.

## ۱) اجرا (یک دستور — از ریشهٔ پروژه)

```bash
bash run-auto.sh
```

> ✅ لازم نیست وارد پوشهٔ اپ شوید. یک لانچر در ریشهٔ مخزن هست که خودش مسیر درست را
> انتخاب می‌کند. اگر از پوشهٔ اپ اجرا کنید هم کار می‌کند — هر دو مسیر پشتیبانی می‌شوند.

### 📖 زبان خروجی روی گوشی

ترمینال Termux خط فارسی را **برعکس و جدا** نشان می‌دهد (بدون پشتیبانی BIDI/شکل‌دهی).
برای همین، روی Termux خروجی **خودکار انگلیسی** می‌شود. اگر فارسی می‌خواهید:

```bash
bash run-auto.sh --lang fa
```

فایل گزارش (`.md`) هم با `--lang en` انگلیسی و با `--lang fa` فارسی نوشته می‌شود.
اگر فارسی خوانا نبود، فایل `.md` را با یک برنامهٔ دیگر (مثل Markdown viewer) باز کنید.

### اگر شک کردید کد به‌روز است یا نه

`bash run-auto.sh --status` را بزنید. سه چیز را نشان می‌دهد:

| خط | معنی |
|---|---|
| `🔖 کامیت` | نسخهٔ کدِ شما |
| `🔄 به‌روز؟ : بله ✅` | همان آخرین نسخه — ادامه بدهید |
| `🔄 به‌روز؟ : خیر ❌` + فهرست کامیت‌ها | کلون عقب است → همان دو دستور پایین را بزنید |

اگر جایی پیام `گزینه‌های ناشناخته` دیدید، **یعنی کلون عقب است**، نه این‌که
دستور غلط است. اول به‌روزرسانی، بعد دوباره همان دستور.

### نکات مهم در طول اجرا

- 📱 **گوشی را روشن نگه دارید.** اگر Termux را ببندید، دانلود قطع می‌شود.
  (اگر `termux-api` نصب باشد، اسکریپت خودش `wake-lock` می‌زند تا گوشی نخوابد:
  `pkg install termux-api -y`)
- 🔌 به شارژ وصل کنید.
- 📶 وای‌فای بهتر از دادهٔ همراه است.
- ⛔ **اگر وسط کار قطع شد، نگران نباشید.** دوباره `bash run-auto.sh` بزنید؛
  داده‌های دانلودشده ذخیره شده‌اند و از همان‌جا ادامه می‌دهد.

### اگر Bybit فیلتر بود

اسکریپت اول شبکه را چک می‌کند و اگر در دسترس نبود، صریح می‌گوید. در آن صورت:

0. 🚀 **فوری‌ترین راه — بدون اینترنت هم کار می‌کند:**
   ```bash
   bash run-auto.sh --offline
   ```
   دادهٔ ۵ سالهٔ BTC و ETH همراه خود پروژه هست؛ همین حالا تحلیل می‌شود
   (۲ نماد → دروازهٔ ۸ نمادی باز نمی‌شود، ولی کل مسیر و خروجی‌ها تست می‌شوند).

1. برای دیدن **علت دقیق** مسدود بودن:
   ```bash
   python3 -m mtflab autoscan --probe-only
   ```
   خروجی مشخص می‌کند «ساعت سرور» باز است یا «دادهٔ کندل» هم بسته شده.

2. VPN/پروکسی را روشن کنید و دوباره اجرا کنید
2. یا اگر آدرس آینه/پروکسی دارید، مستقیم بدهید:
   ```bash
   bash run-auto.sh --base-url https://your-proxy.example.com
   ```
3. یا اگر قبلاً داده گرفته‌اید، فقط تحلیل را دوباره اجرا کنید (آفلاین):
   ```bash
   bash run-auto.sh --source json
   ```

> اگر گفت «دسترسی به حافظه نبود»، یک‌بار `termux-setup-storage` را بزنید و اجازه بدهید.

## ۳.۵) اجرای سناریوی اصلی اسپک (۱۵m / ۱h / ۴h)

تا امروز همهٔ اسکن‌های چندنمادی روی `4h` (فیلتر/بایاس `1d`) اجرا می‌شدند —
یعنی یک **جایگزین**. سناریوی اصلی طراحی (تریگر ۱۵ دقیقه) هرگز روی دادهٔ واقعی
آزموده نشده بود. حالا اجرا می‌شود:

```bash
bash run-auto.sh --tf 15m --tf-filter 1h --tf-bias 4h --days 730 --tag 15m
```

| نکته | توضیح |
|---|---|
| **زمان** | ۱۵m یک‌چهارمِ ۱h است ⇒ ~۷۰٬۰۰۰ کندل در نماد. با `--days 730` و ۲۰ نماد حدود **۴۵–۹۰ دقیقه** (دانلود ~۲۰ دقیقه + بک‌تست). اول با ۳ نماد زمان‌سنجی کنید (پایین) |
| **حجم** | هر نماد ~۷۰٬۰۰۰ کندل ⇒ پوشهٔ `data/json` چند صد مگابایت می‌شود. بعد از ارسال گزارش می‌توانید پاک کنید |
| **قطع شدن** | ایراد ندارد. دوباره همان دستور را بزنید؛ نمادهای تمام‌شده از کش خوانده می‌شوند |
| **زمان‌سنجی اول** | `bash run-auto.sh --tf 15m --tf-filter 1h --tf-bias 4h --days 730 --tag t3 --symbols BTCUSDT ETHUSDT SOLUSDT` — زمان هر نماد را نشان می‌دهد؛ اگر بیش از ۳ دقیقه بود، ۲۰ نماد را نصف کنید |
| **`--days 1460`** | چهار سال ۱۵m = ~۱۴۰٬۰۰۰ کندل در نماد. فقط اگر گوشی و اینترنت خوب است |
| **گرم نگه داشتن** | `termux-wake-lock` بزنید تا اندروید اسکریپت را نکشد |
| **سلامت داده** | هر نماد قبل از ورود به حکم بررسی می‌شود: آخرین کندل باید حداکثر ۲ روز عقب‌تر باشد و بیشتر از ۵٪ کندل‌های بازه غایب نباشد. وگرنه آن نماد **حذف** می‌شود و دلیلش در گزارش می‌آید — به‌جای این‌که بی‌صدا نتیجه را خراب کند |
| **هزینه** | در ۱۵m کارمزد سهم بزرگ‌تری از حرکت است؛ فیلتر هزینه (`min_edge_multiplier`) اینجا واقعاً فعال می‌شود — در ۱h عملاً بی‌اثر بود |

اگر ترکیب تایم‌فریم را اشتباه بدهید (مثلاً فیلتر ریزتر از تریگر)، **قبل از هر
دانلودی** با پیام روشن رد می‌شود:

```
❌ Invalid timeframe stack: `--tf-filter=1h` is finer than the trigger `4h`.
   Hint: --tf 15m --tf-filter 1h --tf-bias 4h
```

خروجی برای من: همان دو فایل `auto_scan_15m.md` و `auto_scan_15m.json` (بخش ۲).

## ۳.۶) انبار داده و زمان (UTC)

هر کندلی که یک‌بار دانلود شد، در `data/json/` می‌ماند و در یک فهرست ثبت می‌شود:

```bash
bash run-auto.sh --data-index          # چه داده‌ای داریم؟ (بدون شبکه)
bash run-auto.sh --data-index --deep   # صحت فایل‌ها را هم چک کن
```

| ستون | معنی |
|---|---|
| `از / تا (UTC)` | اولین و آخرین کندل، به وقت جهانی |
| `وضعیت` | `ok` = فایل سرجایش · `changed` = دست‌کاری/عوض شده · `missing` = پاک شده |

برای تست بعدی **هیچ دانلودی لازم نیست**:

```bash
bash run-auto.sh --source json --tag rerun
```

قواعدی که کد رعایت می‌کند:

- **همه‌چیز UTC است.** زمان کندل‌ها یونیکس میلی‌ثانیه‌اند؛ مرز کندل روزانه
  ۰۰:۰۰ UTC است، نه نیمه‌شب تهران. یک تست مخصوص همین وجود دارد که نتیجه را در
  چهار منطقهٔ زمانی مقایسه می‌کند و باید **دقیقاً یکی** باشد.
- **کش فقط اگر به‌اندازهٔ کافی بلند باشد پذیرفته می‌شود.** اگر یک‌بار ۷۳۰ روز
  گرفته باشید و بعد `--days 1460` بزنید، دوباره دانلود می‌کند — وگرنه گزارش
  «۴ سال» روی ۲ سال داده نوشته می‌شد.
- **دادهٔ ثانیه‌ای یا میکروثانیه‌ای** (CSVهای بیرونی) خودکار به میلی‌ثانیه
  تبدیل می‌شود؛ تاریخ متنی (مثل `2024-01-01`) با خطای روشن رد می‌شود چون
  منطقهٔ زمانی ندارد.

## ۳.۷) بایگانی داده (بعد از هر اجرا)

دادهٔ کامل روی گوشی می‌ماند؛ ۹۰ مگابایت را نمی‌شود در گیت گذاشت. اما
**شناسنامه**اش چند صد کیلوبایت است و همه‌چیز را ثابت می‌کند:

```bash
bash run-auto.sh --archive --tag 15m
```

خروجی: `data_archive/data_digest_15m.json` + `.md`

| داخلش چیست |
|---|
| `sha256` هر فایل (کشف تغییر یک بایت) |
| `content_sha256` روی هر شش ستون OHLCV |
| بازهٔ UTC، تعداد کندل، `days_requested` |
| کندل ماهانه (برای تحلیل خام) + بستهٔ روزانه |
| نمونهٔ ۳ کندل اول و ۳ کندل آخر (عیناً) |

**فقط فایل JSON را بفرستید** — همین برای بایگانی در گیت کافی است.

فایل خودکار به پوشهٔ **Download گوشی** هم کپی می‌شود (اگر `termux-setup-storage`
را یک‌بار زده باشید). اگر کپی نشد، مسیر کامل را خودش چاپ می‌کند.

### بعداً: آیا داده عوض شده؟

پس از هر دانلود دوباره:

```bash
bash run-auto.sh --verify-archive
```

| خروجی | معنی | کار |
|---|---|---|
| `identical` | داده دست‌نخورده | هیچ |
| **`changed`** | صرافی تاریخ را بازنویسی کرده | نتایج قبلی باید دوباره اجرا شوند |
| `moved` | پنجره جابه‌جا شده (پنجرهٔ غلتان) | طبیعی است، هش قابل مقایسه نیست |
| `missing` | آن نماد در یک طرف نیست | اگر عمدی نبوده، نگاه کن |

## ۳.۸) تحلیل هزینه — «آیا هزینه کشنده است یا سیگنال؟»

**چرا این مهم است:** هر بهبود اجرا (سفارش محدود، کارمزد میکر، اسلیپیج صفر) فقط
یک کار می‌کند: هزینه را کم می‌کند. پس بهترین چیزی که می‌تواند بدهد، همان حالت
«هزینهٔ صفر» است. اگر با هزینهٔ صفر هم سودده نبود، هیچ اجراگذاری نجاتش نمی‌دهد.

```bash
bash run-auto.sh --sweep --tf 4h
```

بدون دانلود، روی دادهٔ ذخیره‌شده. حدود ۲ دقیقه برای ۲۰ نماد و دو نسخه (`trend` و `base`).

> **اگر فایل را پیدا نکردید:** گزارش، مسیر **مطلق** فایل را چاپ می‌کند و خودش آن را
> در پوشهٔ Download گوشی کپی می‌کند. اگر Download در دسترس نبود، همان‌جا می‌نویسد
> فایل‌ها کجا هستند و دستور کپی را هم چاپ می‌کند. فایل‌ها همیشه اینجا هم هستند:
> `my_project/apps/futures-mtf-lab/results/cost_sweep.*`

### چه چیزی اندازه می‌گیرد

| سیاست | ورود | خروج | هزینهٔ رفت‌وبرگشت |
|---|---|---|---:|
| `taker` | بازار ۵.۵bps + ۰.۰۲٪ | بازار | ۱۵ bps |
| `taker_noslip` | بازار بدون اسلیپیج | بازار | ۱۱ bps |
| **`maker_tp`** ★ | بازار | **حد سود = سفارش محدود** | **۹.۵ bps** |
| `all_maker` | همه میکر (غیرواقعی) | همه میکر | ۴ bps |
| `zero` | صفر | صفر | ۰ bps |

`maker_tp` واقع‌بینانه‌ترین است: در معاملهٔ الگوریتمی ورود و حد ضرر بازارند، ولی
حد سود یک سفارش محدودِ نشسته است. مدل قبلی هر دو پا را تیکر می‌گرفت — یعنی
**بدبینانه‌تر از واقعیت** بود.

### چطور بخوانید — حکم خودکار

گزارش در خط اول یک «حکم» می‌دهد. سه حالت ممکن است:

| حکم | معنی | کار بعدی |
|---|---|---|
| ❌ **رها کنید** | با هزینهٔ صفر هم PF ≤ ۱ | مسئله سیگنال است، نه اجرا |
| ✅ **طرح میکر ارزش ساخت دارد** | با `maker_tp` هم PF > ۱ | اجراگذاری محدود را بسازید |
| ⚠️ **مرزی** | فقط با `all_maker` بالای ۱ می‌رود | نسازید؛ حد ضرر را نمی‌توان محدود گذاشت |

**نکتهٔ کلیدی که گزارش نشان می‌دهد:** بخش «معامله‌ها چطور بسته می‌شوند» سهم
خروج‌هایی را می‌دهد که اصلاً می‌توانند محدود باشند. حدود دوسومِ خروج‌ها حد ضرر و
تریلینگ‌اند و **ماهیتاً سفارش بازارند**. پس اگر آن سهم کوچک باشد، ستون `maker_tp`
عملاً همان `taker` است و سودِ `all_maker` یک سراب است.

## ۳.۹) مدیریت خروج هر ۱۵ دقیقه — «کندل ۴ ساعته باز، ولی دقیقه‌به‌دقیقه دیده شود»

```bash
bash run-auto.sh --exec-scan
```

بدون دانلود. تصمیم **ورود** روی ۴ ساعته گرفته می‌شود، ولی پوزیشن باز با کندل
های **۱۵ دقیقه** مدیریت می‌شود: ۱۶ بررسی در هر کندل ۴ ساعته، نه یکی. حدود
۵ دقیقه برای ۱۶ نماد. دو فایل می‌سازد و به Download می‌گذارد: `exec_tf.md` و
`exec_tf.json`.

**به داشتن داده نیاز دارد:** هم `*_4h.json` و هم `*_15m.json` در `data/json/`.
از اجرای قبلی هر دو را داری. نمادهایی که فقط یک تایم‌فریم دارند، در گزارش
جدا فهرست می‌شوند و حذف می‌شوند (بی‌صدا نادیده گرفته نمی‌شوند).

### سه تنظیم — بدون جست‌وجو، از قبل قفل‌شده

| کد | چیست |
|---|---|
| `A_base` | پایه: همه چیز مثل امروز (۴ ساعته، بدون قاعدهٔ افت سود) |
| `B_fine` | خروج روی ۱۵ دقیقه: ترتیب واقعی لمس حد ضرر/حد سود + تریلینگ ۱۶ برابر سریع‌تر |
| `C_fine_gb` | همان `B` + **قاعدهٔ افت سود**: اگر سود شناور به +۱R رسید و بعد به ۵۰٪ اوجش برگشت، ببند |

### چرا «دقت مسیر» واقعاً مهم است

یک کندل ۴ ساعته می‌تواند هم سقف را لمس کند هم کف. مدل ۴ ساعته **نمی‌داند**
کدام اول بود، پس محافظه‌کارانه حد ضرر را فرض می‌کند. مدل ۱۵ دقیقه‌ای می‌داند.
این تنها جایی است که این ایده می‌تواند نتیجه را عوض کند — و تست
`test_fifteen_minute_detail_knows_the_take_came_first` همین را قفل کرده است.

### معیار قبولی — از قبل نوشته شده

| شرط | حد |
|---|---|
| میانهٔ PF | ≥ **۱.۱۲۰۱** (پایهٔ امروز) |
| نمادهای PF>1 | ≥ **۱۵** از ۲۰ |
| سهم ۵ سکهٔ اول از سود | **< ۷۰٪** |

هر سه باید **هم‌زمان** پاس شوند. PF بهتر با تمرکز بیشتر روی چند سکه، قبولی
نیست — همان دام overfitting است. حکم در ستون «قبولی» گزارش می‌آید.

## ۳.۱۰) آزمون قله/دره و «استراحت بعد از سود»

```bash
bash run-auto.sh --trade-lab
```

بدون دانلود، روی دادهٔ ۴ ساعتهٔ ذخیره‌شده. سه فایل می‌سازد و در Download
می‌گذارد: `trade_lab.md`، `trade_lab.json` و `trades_export.json`.

این یک اجرا، **دو سؤال** را جواب می‌دهد — و `trades_export.json` را نگه دارید،
چون هر آزمون آیندهٔ دیگری هم می‌شود روی همان اجرا کرد، بدون اجرای دوباره.

### آزمون ۱ — جایگاه قیمت میان قله و دره

۰ = روی دره · ۱ = روی قله · بالای ۱ = محدوده شکسته.

قله و دره **تأییدشده** حساب می‌شوند: یک قله فقط وقتی قله است که ۳ کندل بعدش هم
پایین‌تر باشد. یعنی قله در همان کندل معلوم نمی‌شود — همان نکته‌ای که جلوی نگاه
به آینده را می‌گیرد.

خرگوش این آزمون **پنجک‌بندی** است، نه جست‌وجوی آستانه: همهٔ معاملات به ۵ گروه
بر اساس نسبت تقسیم می‌شوند و میانگین هر گروه مقایسه می‌شود. اگر ویژگی اطلاعات
داشته باشد، این پنج عدد یکنوا بالا یا پایین می‌روند.

| دروازه (از قبل) | حد |
|---|---|
| اختلاف پنجک ۱ و ۵ | ≥ **۰.۳۱R** |
| معناداری | \|t\| ≥ ۲ |
| حداقل معامله در هر پنجک | ۶۰ |

### آزمون ۲ — «بعد از سود، سود را پس می‌گیرند؟»

پنج قاعده، همه از پیش تعیین‌شده (ترکیب زمان **و** ساختار، همان چیزی که
خواسته شد):

| قاعده | چیست |
|---|---|
| ۴ کندل صبر | بعد از هر برد، ۴ کندل (۱۶ ساعت روی ۴ ساعته) معامله نکن |
| ۴ کندل + تغییر ساختار | همان، ولی اگر ساختار بازار عوض شد، زودتر آزاد شو |
| ۲۰ کندل + تغییر ساختار | ≈۳ روز صبر |
| معاملهٔ بعدی | فقط معاملهٔ بعدیِ همان نماد را رد کن |
| معاملهٔ بعدی + تغییر ساختار | همان + آزادشدن با تغییر ساختار |

**دروازه:** بهبود expectancy باید ≥ **۰.۰۶R** باشد **و** از باند نویز بیرون بزند.
باند نویز با جابه‌جایی تصادفی برچسب برد/باخت درون هر نماد ساخته می‌شود — یعنی
همان قاعده روی داده‌ای که در آن اثر وجود ندارد اجرا می‌شود.

> اگر خروجی «⚪ بی‌اثر (هیچ معامله‌ای حذف نشد)» دیدید، یعنی معاملات آن‌قدر از هم
> دورند که ۴ کندل صبر هیچ اثری ندارد. این خودش یک یافته است، نه خطا.

## ۳.۱۱) اتوترید مجازی — رصد اعتبار سیگنال‌ها

```bash
bash run-auto.sh --live            # یک گام: دادهٔ تازه، سیگنال تازه، گزارش
bash run-auto.sh --live --status   # فقط گزارش وضعیت (بدون گرفتن داده)
```

این «ربات معامله» نیست — **دفترچهٔ رصد** است. هیچ سفارشی به صرافی نمی‌رود،
هیچ کلید API نمی‌خواهد، و همه‌چیز روی حسابِ خیالی (شروع: **۱۰۰۰$**) جلو می‌رود.
هدفش این است که ببینیم سیگنال‌های همین الگوریتم که الان نهایی است، در آینده
چه اعتباری دارند — بدون این‌که دوباره پارامتر عوض کنیم.

### هر اجرا چه می‌کند

۱. کندل‌های بستهٔ تازه را می‌گیرد (کندل نیمه‌کاره هیچ‌وقت استفاده نمی‌شود).
۲. فقط روی کندل‌هایی که **قبلاً ندیده** جلو می‌رود (شمارندهٔ `last_bar_ms` در
   `results/live/state.json`) — اجرای دوباره سیگنال تکراری نمی‌سازد.
۳. سیگنال را با **انتساب کامل** در `results/live/journal.jsonl` ثبت می‌کند.
۴. خروج‌ها را با قاعده‌ای که بست ثبت می‌کند و به همان سیگنال پیوند می‌دهد.
۵. گزارش فارسی `results/live_report.md` را می‌نویسد و در Download می‌گذارد.

### دو سؤالی که هر رکورد جواب می‌دهد

- **این سیگنال مالِ کدام الگوریتم بود؟** `algorithm.id` (مثل `trend`)،
  `algorithm.label`، `cfg_digest` (انگشت‌نگاری پارامترها) و `tf`.
- **چه الگویی سیگنالش کرد؟** `entry_pattern.mode` (breakout / pullback)،
   رژیم فیلتر و بایاس، دلیل تریگر و دلیل تصمیم، confidence و score.
- **چه چیزی بستش؟** `closed_by.rule` + یعنی‌فارسی‌اش + پرچم
  `is_risk_control` — یعنی **صریحاً معلوم است که آیا یک قاعدهٔ ضدضرر بستش یا نه**.

نمونهٔ یک رکورد بستن:

```json
{"type":"close","id":"BTCUSDT:trend:1704787200000:closed",
 "open_id":"BTCUSDT:trend:1704787200000",
 "closed_by":{"rule":"stop_trail","fa":"تریلینگ استاپ (ATR×ضریب)",
              "is_risk_control":true},
 "result":{"pnl":6.55,"r_multiple":0.65,"mfe_pct":1.93,"bars_held":18}}
```

`open_id` همان شناسهٔ سیگنال است. با یک `grep` می‌شود کل پروندهٔ یک معامله را دید:

```bash
grep "BTCUSDT:trend:1704787200000" results/live/journal.jsonl
```

### گزارش

| بخش | چه می‌گوید |
|---|---|
| سرمایه / اوج / افت | حساب مجازی چقدر جلو رفته |
| کدام الگوریتم، چند سیگنال | نرخ برد و expectancy هر الگوریتم (به R) |
| کدام قاعده بست | سهم هر قاعده + ✅ اگر ضدضرر بود |
| آخرین سیگنال‌های بسته‌شده | هر سیگنال: ورود، خروج، R، سود، قاعدهٔ بست |
| سیگنال‌های باز | با الگو و الگوریتم، برای این‌که بدانی الان چه چیزی در جریان است |
| سیگنال‌هایی که رد شدند | چرا وارد نشد: جایگاه پر بود، فیوز ضرر پیاپی، استراحت بعد از ضرر، سقف ضرر روزانه |

### حلقهٔ تکرار (روی گوشی)

هر ۴ ساعت یک کندل ۴ ساعته بسته می‌شود؛ پس روزی ۶ بار کافی است. این را در
Termux بزن و بگذار باز بماند:

```bash
while true; do
  bash run-auto.sh --live
  echo "--- خواب ۱ ساعت ---"
  sleep 3600
done
```

چرا ۱ ساعت و نه ۱۵ دقیقه؟ کندل ۴ ساعته است؛ داده تا سرِ کندل بعدی عوض نمی‌شود
و کشِ CSV همان را می‌خواند. پس اجرای ساعتی هم `bars=0` می‌دهد و هم درخواست
بی‌مورد به Bybit نمی‌فرستد.

اگر می‌خواهی فقط نگاه کنی و چیزی نخوابانی:

```bash
bash run-auto.sh --live --status
```

### نکته‌های مهم

- **دادهٔ کم = تاریخچهٔ کم.** اولین اجرا با `--backfill` (پیش‌فرض ۱۲۰ کندل)
  تاریخچه را از نو می‌سازد تا گزارش از روز اول خالی نباشد. این معاملات در
  ژورنال `"backfilled": true` دارند و با معاملات واقعیِ آینده قاطی نمی‌شوند.
- **پنجرهٔ داده کوچک نشود.** اگر بعداً با `--days` کمتر اجرا کنی و پوزیشنی
  قدیمی‌تر از پنجره باز باشد، پوزیشن دور ریخته **نمی‌شود**؛ با علامت
  `restore_gap` در حالت می‌ماند و از آخرین کندل مدیریت می‌شود.
- **دست نزن به پارامترها.** هر تغییری در پارامترها `cfg_digest` را عوض می‌کند؛
  یعنی سیگنال‌های قبل و بعد از تغییر دیگر یک خانواده نیستند. رصد فقط وقتی معنا
  دارد که الگوریتم ثابت بماند.
- **پاک کردن از صفر:** `rm -rf results/live results/live_report.*`

## ۳.۱۲) داشبورد کارگاه — «اتوترید» + «آزمایشگاه تنظیمات»

```bash
bash run-auto.sh --dash                 # داشبورد + یک قدم زنده
bash run-auto.sh --dash --no-step       # فقط داشبورد، بدون گرفتن داده
bash run-auto.sh --dash --every 3600    # داشبورد + حلقهٔ خودکار هر ۱ ساعت
```

بعد در مرورگر گوشی این را باز کن:

```
http://127.0.0.1:8770
```

هیچ چیز از اینترنت بارگذاری نمی‌شود (نه فونت، نه کتابخانه) — پس روی گوشیِ
بی‌اینترنت هم باز می‌شود. فقط PAPER است؛ نه کلید API، نه سفارش واقعی.

### چهار تب

| تب | چه می‌دهد |
|---|---|
| **زنده** | سرمایهٔ مجازی، افت، سیگنال‌های باز، آخرین بسته‌شده‌ها، و «چرا وارد نشد». دکمهٔ «قدم بعدی» یک قدم تازه می‌زند. |
| **سیگنال‌ها** | فهرست همهٔ سیگنال‌ها با فیلتر (نماد، قاعده، ضدضرر، باز/بسته). روی هر ردیف بزن تا **پروندهٔ کامل** همان سیگنال باز شود. |
| **آزمایشگاه** | ۲۷ تنظیم (ریسک، خروج، ورود، ساختار) + انتخاب نماد + **دروازه‌ای که قبل از اجرا می‌نویسی** → نتیجهٔ همان لحظه، با Δ، بازهٔ اطمینان و بخش بیرون‌نمونه. |
| **آزمایش‌ها** | همهٔ آزمایش‌ها با شمارهٔ ترتیب، هش تنظیمات و حکم دروازه. هیچ آزمایشی پاک نمی‌شود. |

### سه چیزی که عمداً سخت‌گیرانه گذاشته شده

۱. **شمارهٔ آزمایش**: هر اجرا می‌گوید «این چندمین آزمایش روی همین داده است» و
   احتمال این‌که دست‌کم یکی شانسی خوب به نظر برسد را می‌نویسد.
۲. **بازهٔ اطمینان Δ**: بهبود نسبت به خط پایه با بوت‌استرپ ۹۰٪ سنجیده می‌شود؛
   اگر بازه صفر را دربر بگیرد، یعنی «قابل اثبات نیست».
۳. **بخش بیرون‌نمونه**: ۳۰٪ آخرِ بازهٔ زمانی جدا سنجیده می‌شود. تغییری که فقط در
   گذشتهٔ دور خوب بوده، این‌جا لو می‌رود.

### نکتهٔ مهم دربارهٔ داده

آزمایشگاه روی **همان دادهٔ کش‌شده** اجرا می‌شود (بدون شبکه) و کش‌ها را در
`data/json` نگه می‌دارد. آزمایش‌ها در `results/live_lab/` ذخیره می‌شوند (در گیت
نمی‌روند). اگر داده تازه خواستی، در تب زنده «قدم بعدی» را بزن یا در Termux
`bash run-auto.sh --live` را اجرا کن.

## ۴) قاعدهٔ پذیرش — از قبل تعیین شده

این قاعده **قبل از دیدن نتیجه** نوشته شده و بعد از دیدن نتیجه تغییر نمی‌کند.
یک نسخه فقط وقتی «قبول» است که **همهٔ** این‌ها را داشته باشد:

| شرط | حد |
|---|---|
| تعداد نماد با دادهٔ کافی | ≥ ۸ |
| نمادهای با PF>1 | ≥ ۶۰٪ |
| سال‌های مثبت | ≥ ۶۰٪ |
| میانهٔ PF | ≥ ۱.۰۵ |
| معناداری در برابر نسخهٔ پایه | p ≤ ۰.۱۰ |
| حداقل معامله | ≥ ۱۰۰ |

اگر هیچ نسخه‌ای قبول نشد، **این هم یک نتیجه است** — و همان را می‌نویسیم.
فهرست ۲۰ نماد هم داخل کد ثابت است تا بعد از دیدن نتیجه عوضش نکنیم.
