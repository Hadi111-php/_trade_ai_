# راهنمای داشبورد — بدون اصطلاح فنی

> این صفحه برای «اولین بار» است. سه چیز را یاد بگیری، بقیه‌اش را خودت می‌فهمی:
> **کجا کلیک کنم، کدام عدد را نگاه کنم، کِی دست نگه دارم.**

## ۰) این داشبورد چه هست و چه نیست

- **هست:** یک اتاق تمرین. سیگنال می‌سازد، معاملهٔ **مجازی** باز می‌کند، ضرر و سود
  را روی پولِ خیالی حساب می‌کند و همه‌چیز را مکتوب نگه می‌دارد.
- **نیست:** ربات معامله با پول واقعی. هیچ سفارشی به صرافی نمی‌رود، هیچ کلید API
  لازم نیست.

## ۱) بازکردن

```bash
cd ~/lab/my_project/apps/futures-mtf-lab
bash run-auto.sh --dash
```

نشانی‌ای که چاپ می‌شود (مثل `http://127.0.0.1:8770/`) را در مرورگر گوشی بزن.
اگر `termux-api` نصب باشد، خودش باز می‌شود. برای بستن: `Ctrl+C`.

## ۲) پنج تب، در یک خط

| تب | برای چه |
|---|---|
| **زنده** | وضعیت همین حالا: سرمایهٔ خیالی، معاملات باز، «چرا وارد نشد» |
| **سیگنال‌ها** | آرشیو؛ روی هر ردیف بزن تا پروندهٔ کاملش باز شود |
| **آزمایشگاه** | اینجا تنظیمات را عوض می‌کنی و روی همان داده نتیجه می‌بینی |
| **آزمایش‌ها** | دفتر همهٔ اجراها؛ هیچ‌کدام پاک نمی‌شود |
| **مغز دوم** | نظر یک مشاور کوچک؛ تصمیم را عوض نمی‌کند |

## ۳) سه عددی که تصمیم را می‌سازند

1. **تعداد معامله (n)**: زیر ۳۰ = هیچ نتیجه‌ای نگیر. با ۳ معامله فقط می‌شود
   گفت «سیستم روشن است»، نه «خوب است».
2. **expectancy (R)**: میانگین سود هر معامله به واحد ریسک. صفر = سربه‌سر.
   منفی = هزینه و ضرر بیشتر از سود.
3. **بیرون‌نمونه (۳۰٪ آخر)**: اگر این منفی است، بقیهٔ جدول را باور نکن.

## ۴) یک دور کامل تمرین (۵ دقیقه)

1. تب **آزمایشگاه** → دروازهٔ قبولی را **قبل** پر کن:
   حداقل ۳۰ معامله، expectancy ≥ ۰، بیرون‌نمونه مثبت ✅.
2. الگو را انتخاب کن (مثلاً `trend`) و **یک** پارامتر را عوض کن (مثلاً تریل ۴×ATR).
3. «اجرای آزمایش». نتیجه را بخوان: n، expectancy، Δ با خط پایه، و بسته‌شدن با
   هر قاعده.
4. اگر ترکیب به‌دردبخوری بود، اسم بگذار و «ذخیره به‌عنوان تیم» بزن.
5. تب **آزمایش‌ها** → ببین شمارهٔ آزمایش چند شد. هرچه بیشتر بگردی، احتمال
   «شانسی بودن بهترین» بیشتر می‌شود.

## ۵) «ضرر کرد، اشتباه بود؟»

اول **قاعدهٔ بست** را نگاه کن (تب سیگنال‌ها):

| قاعدهٔ بست | معنی |
|---|---|
| حد ضرر / تریلینگ / سربه‌سر | ✅ سیستم کارش را کرده؛ ضرر را کوچک نگه داشته |
| سقف زمان | ⚠️ فرصت تمام شد؛ باید بررسی شود |
| پایان داده | ⚠️ فقط در بک‌تست معنا دارد، در رصد زنده نباید باشد |

قاعدهٔ تجربی: هر ضرر سالم **حدود ۱R** است (اگر ریسک هر معامله ۱۰ دلار باشد،
ضرر ≈ ۱۰ دلار). ضرر ۱.۸R یعنی لغزش یا گپ — آن خطاست، نه بازار.

برای بازبینی دقیق:

```bash
python3 -m mtflab audit --journal results/live/journal.jsonl --out results/audit_fa.md
```

## ۶) پنج قانون طلایی

1. با سه معامله قضاوت نکن. با نرخ برد ۳۵٪، سه ضرر پشت‌سرهم در ≈۲۷٪ مواقع رخ می‌دهد.
2. دروازه را **قبل** از دیدن نتیجه بنویس؛ بعد از دیدن، فقط توجیه می‌نویسی.
3. پارامتر عوض کردی = یک آزمایش به دفتر اضافه شد. پنجاه آزمایش = پنجاه نگاه.
4. دادهٔ نمایشی (`--demo`) ساختگی است؛ برای یادگیری دکمه‌ها خوب، برای نتیجه بد.
5. «تیم» یعنی یک دسته تنظیماتِ نام‌دار، نه یک لبهٔ تأییدشده.
